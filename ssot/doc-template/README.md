# ssot/doc-template — 스펙 문서 공통 양식

`/spec`이 만드는 유닛 스펙 문서의 양식 자산. jojo 워크플로우 킷 `2-ssot/doc-template/`에서 이식 (2026-08-29). 2026-09-06 가독성 개정: 판정 블록 선두 · 근거 각주화 · 리스트 문법 · 읽은 목록 접힘.

## 두 파일의 역할

| 파일 | 읽는 쪽 | 내용 |
|------|------|------|
| `<유닛>.src.html` | AI (`/plan` · `/build` 입력) | 원문. 근거가 주장 바로 옆에 `<span class="fn">…</span>` 로 인라인. 에셋은 경로 참조 |
| `<유닛>.html` | 사람 (게이트 판정) | 빌드 결과. 근거는 번호 각주로 최하단에 몰리고 클릭 팝오버로 뜬다. 폰트·이미지 인라인 자립 |

AI 용 문서를 따로 만들지 않는다. src 가 곧 AI 용이다.

## 파일

| 파일 | 내용 |
|------|------|
| `template.src.html` | 문서 스켈레톤. 새 스펙 문서는 이 파일 복제로 시작한다 |
| `_build.py` | `<문서>.src.html → <문서>.html`. `assets/...` 인라인(이미지 · .ttf/.otf 는 서브셋 woff2) + 매니페스트 폰트 서브셋 임베드 + 각주 번호 매김. 외부 URL 잔존·src 내 폰트 base64 시 실패. 요구: python3 + fonttools + brotli |
| `fonts/` | KoPub Batang·Dotum(300/500/700), Fraunces(400/600) 등 + manifest.json |
| `assets/fonts/DeogonMock.ttf` | 무대 목업용 인게임 대역 폰트. src 에서 `url('assets/fonts/DeogonMock.ttf')` 로 참조 |
| `assets/icons-a/` | Phosphor 아이콘 (템플릿이 참조) |

빌드는 프로젝트 루트에서:

```bash
python3 ssot/doc-template/_build.py notes/<유닛>/<유닛>.src.html
```

## 문서 구조

```
헤더 (날짜 · meta 1줄 · 제목 · 두 문장)
00 판정      ← 사용자가 답할 것만. 열린 D-NN + 판정 축. 선택지 + 메모 → MD 회신 복사
목차
01 방향 / 02 정책 / 03 화면 / 04 규격 / 05 시스템 영향   (해당 없는 절만 뺀다 · 번호는 문서마다 매김)
주 각주 · 근거  ← 빌드가 채운다 + 읽은 목록(접힘) + 부칙(라운드 1줄씩)
```

### 00 판정 블록 (`section.verdict#s-verdict`)

- `data-unit` · `data-round` · `data-gate` 가 MD 회신 제목이 된다. `data-state="open"` = 게이트 대기, `"closed"` = 컨펌 뒤.
- 항목(`.vitem[data-k]`) = 열린 D-NN 과 판정 축 ①②③. `.vt` 축 이름 · `.vq` 선택지가 바꾸는 것 한두 문장(근거는 각주) · `.opts` 라디오 · `.memo` 텍스트.
- D-NN 선택지의 첫 항목이 권고안이고 `checked`. 판정 축은 확정 / 수정 2택.
- 컨펌되면 `data-state="closed"` 로 바꾸고 `.stamp` 에 날짜, 각 `.vq` 를 확정 결과 1문장으로 바꾼다. 해소된 D-NN 의 선택지 서술은 지운다 (결정 이력은 부칙 1줄).
- `/plan` 은 `data-state="closed"` 를 컨펌 신호로 읽는다.

### 각주

- 저자는 주장 문장 끝에 `<span class="fn">출처 · 파일:줄 · 선례 · 산출 시점</span>` 로 쓴다. 본문에는 주장만 남긴다.
- 빌드가 문서 순서로 번호를 달아 `<sup>` 마커로 바꾸고 `<!--__FOOTNOTES__-->` 자리에 목록을 넣는다. 클릭하면 마커 우상단에 팝오버.
- 각주 안에 `span` 금지 (`code` · `b` · `i` · `a` 만). 각주는 근거를 «옮기는» 자리다. 근거를 «지우는» 자리가 아니다 (`/plan` 이 데이터 계약을 실측에서만 가져온다).
- 규격표의 «근거» 열은 두지 않는다. 값 뒤 각주로.

### 리스트와 표

- 병렬 항목이 3개 이상이면 본문이든 표 셀이든 `<ol>`/`<ul>` 로 한 항목 한 줄. 셀 하나에 ①②③ 을 가운뎃점(·)으로 잇지 않는다. 리스트 뒤 단서 문장은 `<span class="then">` 으로 별도 줄.
- 표는 상태×화면×전이 같은 2차원 데이터에만 쓴다. «원칙 · 정의» 같은 1차원 나열은 `h4` + 문단.
- `<code>` 인라인은 독자가 그 이름으로 가야 하는 식별자에만. 파일:줄 · 선례 · 실측 시점은 각주로.

### 그 밖의 규율

- 정책은 `/build`가 추가 질문 없이 구현할 수 있는 수준까지 (상태 전이·경계 케이스·기본값).
- 문구는 `ssot/tone/` 확정본 글자 그대로, 신규는 규격표에 표시. 더미 문구 금지.
- 읽은 목록(감사용)은 `details.audit` 안에 접는다. 부칙은 라운드당 1줄.
- 목업 폰트·이미지를 src 에 base64 로 박지 않는다. `assets/` 경로로 참조하고 빌드가 인라인한다.
- `@media` 블록은 스타일시트 최후미에.
- 토큰 블록(`:root`)은 킷 이식 초기값이다 — FACE 문서 화풍(먹·한지 등)으로 갈지는 미결 (phase3-draft-report D-02). 확정되면 이 템플릿의 `:root`를 정본으로 삼고 임의 수정을 금지한다.
