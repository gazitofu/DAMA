# 06. 테스트 및 합격 기준

## 1. 테스트 층위

이 패키지에 포함한 테스트는 **합성 데이터의 계약/결합 규칙 테스트**다. 실제 macOS 앱, 마이크, 유료 API, WhisperKit 모델 추론을 실행한 결과가 아니다. 각 검증 층위를 따로 보고한다.

| 층위 | 대상 | 실행 환경 |
|---|---|---|
| 계약 | JSON schema, 참조/시간/순서 불변식 | Python / Swift Core |
| pure logic | 후보 점수, overlap, marker, Turn 병합 | Swift Core, 합성 fixture |
| HTTP mock | upload/submit/poll, auth 분리, 재시도 | URLProtocol mock |
| 저장 fault injection | 파일 중간 저장, active pointer, 종료 복구 | 임시 테스트 디렉터리 |
| 실기기 기능 | 마이크/권한/메뉴바/원음 seek/동시 부하 | 사용자 Mac |
| 실제 모델 품질 | 한국어 E1/E2/누락/unknown/검수시간 | 동의받은 실제 회의 |

## 3. 녹음/실기기 테스트

녹음 시작 후 창 닫기/다른 앱 전환/메뉴바 재열기를 반복한다. 한 번 클릭당 한 번만 상태 전환되어야 한다. API 키 제거, 비행 모드와 유사한 네트워크 차단, 전사 실행 중 새 녹음도 테스트한다.

10분 기능 테스트 뒤 2시간 연속 녹음 시험을 제안한다. 이것은 검증할 목표이지 현재 앱의 검증된 최대 길이가 아니다. 원본 프레임 수, 정상 종료 오디오 길이, writer queue overflow, peak memory, 파일 크기, 재생 끊김 여부를 기록한다. 메모리는 전체 오디오 길이에 비례해 계속 늘지 않아야 한다.

강제 종료는 청크 확정 직전/직후, 업로드 중, submitting 직후, response 저장 후 parsing 전, revision 저장 중에 각각 주입한다. 이미 확정한 파일이 손상되지 않고 원래 상태를 복구하는지 확인한다. force quit와 갑작스러운 전원 손실은 같은 보장으로 묶지 않는다.

수면/덮개 닫힘/장치 변경/마이크 권한 해제/디스크 부족에서는 녹음 중단 사실이 저장되어야 한다. UI만 Recording인 채 실제 오디오가 없는 상태를 감지한다. 무음을 모두 오류로 판단하지 않도록 callback 수신과 실제 음량은 별도로 감시한다.

## 4. 네트워크/보안 테스트

API Bearer 헤더가 서명 PUT URL에 붙지 않아야 한다. redirect를 모의해 다른 host로 인증 정보가 전달되지 않는지 확인한다. POST의 응답을 유실시키고 자동 중복 job이 생성되는 경로가 없는지 테스트한다. GET retry는 같은 jobId를 사용해야 한다.

snapshot/log/crash message/export에서 API 키, Authorization, 서명 URL query, 절대 파일 경로, 원문 로그를 검색한다. 개인정보를 포함한 fixtures를 저장소에 추가하지 않는다. 테스트 음성은 사용자 동의받은 파일을 gitignored 폴더로만 보관한다.

## 5. 실제 한국어 평가 설계

기존에 TIRO/클로바노트에서 문제가 컸던 파일을 우선 사용한다. 최소 3개의 서로 다른 회의에서 10~20분씩 구간을 제안하되, 최종 검증은 전체 회의 단위 출력에서도 수행한다. 같은 성별/비슷한 음색, 짧은 맞장구, 원거리 화자, 동시에 말함, 기술명/영어 혼용을 포함한다.

사람이 원음을 들으며 reference를 만든다. 레이블 A/B/C의 이름 자체는 임의이므로, 비교 전에 참조 화자와 예측 화자 사이의 전역 매핑을 정한다. 시간순으로 화자가 바뀔 때마다 편의상 ID를 다시 매핑하면 오귀속이 숨겨지므로 금지한다.

### 사용자 문제와 직접 연결되는 지표 — 이 앱의 평가 정의

1. **E1 오귀속률**: 참조와 매칭된 lexical unit 중, 잘못된 '확정 화자'로 배정한 개수 / 매칭 가능한 참조 unit 수. unknown은 별도 집계한다. 텍스트 오인식/삭제로 매칭 불가한 수를 따로 보고한다.
2. **E2 화자 전환 누락률**: 참조 화자 전환에서 ±250ms 내 표현된 화자 전환 또는 검수 marker가 없는 수 / 참조 전환 수. 자동으로 맞힌 전환과 marker만 남긴 전환도 따로 집계한다. tolerance는 평가용 제안값이다.
3. **짧은 발화 누락률**: 참조상 1초 이하의 실제 발화 중 대응 텍스트가 없는 수 / 해당 발화 수. marker만 있어도 ASR 복구 성공으로 세지 않는다.
4. **unknown 비율**: 화자 미확정 lexical unit / 전체 출력 lexical unit. E1과 반드시 함께 제시한다.
5. **검수시간**: 동일 분량을 사람이 실용적으로 사용할 수 있게 수정하는 데 걸린 시간과 수정 횟수.

한국어 텍스트 오인식은 CER도 보조 기록할 수 있다. 공백/문장부호/숫자/영문 정규화 규칙을 먼저 고정하고 원문 점수도 별도 보존한다. 이 패키지는 표준 DER 계산기를 구현하지 않으며 위 지표를 DER이라고 부르지 않는다.

모든 값을 하나의 가중 합계로만 숨기지 않는다. 표본 수/총시간/화자 수/동시발화 비율/모델 revision/설정을 함께 기록한다. 통합 API와 Hybrid를 동일 입력으로 비교하고, 더 느리거나 검수 부담이 늘면 Hybrid를 기본으로 승격하지 않는다.

## 6. P0 release gate

G-01: 원클릭 녹음, 패널 종료와 수명 독립, 오프라인 녹음 통과.

G-02: 정상 종료 원본 손상/프레임 누락 없음. 강제 종료에서 확정 청크 복구 통과; 마지막 미확정 구간의 제한 명시.

G-03: 제공된 계약/회귀 테스트와 Swift 이식 테스트 전부 통과.

G-04: 키/서명 URL/원문이 로그와 export에 노출되지 않음.

G-05: 유료 API 실제 테스트를 별도 수행하고, 접수 불명/결과 만료 처리 확인.

G-06: 원음 듣기 → 화자 수정 → Undo → 재실행 → JSON/TXT export 검증.

G-07: 한국어 실제 파일에서 E1/E2/누락/unknown/검수시간 보고. 이 단계가 없으면 '정확한 화자 분리 검증 완료'라는 문구 사용 금지.

G-08: M3나 시스템 오디오를 구현하지 않았다면 UI/문서에서 미구현을 명시하고 production 기본 경로로 노출하지 않음.
