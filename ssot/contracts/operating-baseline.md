# DAMA 운영·비교·승격 계약

2026-09-11 사용자 최종안. 목표는 **TIRO보다 낮은 현금 비용으로, TIRO·클로바노트보다 화자와 핵심 의미를 잘 보존하는 원문 스크립트**다. 특정 모델 채택은 목표가 아니다. 구현 상태 정본은 [plan](../../versions/operating-baseline/plan.md).

## 운영과 실험

| 경로 | 역할 | 실행 |
|---|---|---|
| Soniox 전사 + Precision-2 | 당분간 운영 기본 | 새 녹음별 확인 후 두 공급자 각각 1회 또는 동일 조건의 결과 재사용 |
| Soniox 자체 화자 결과 | 결합의 추가 가치를 판단하는 비교본 | 위 Soniox Run을 그대로 보존; 비교용 추가 전사 없음 |
| Qwen3-ASR + ForcedAligner + 동일 Precision-2 | 선별 실험 | 사용자 선택 시만 실행, AI 교정 OFF; 운영에 자동 개입 없음 |
| pyannote 통합 전사 | 업데이트·정기 재평가용 | 고정 표본에서 별도 선택. 기존 STT 품질이 개선됐다고 추정하지 않음 |
| TIRO·클로바노트 | 외부 기준 | 같은 원음으로 별도 실험 승인/실행. 현재 미수행 |

새 선택의 기본값은 `sonioxPrecision`. 이전 사용자의 엔진 선택은 새 운영 선택 저장 키와 분리해 1회 초기화하며 이후 선택은 유지한다. 구 Run의 미기록 공급자는 pyannote로 해석한다. Qwen 설정·체크포인트·완료 비교 결과는 보존한다. 중단된 Qwen은 새 운영 전사를 막지 않지만 실행 중 작업은 동시에 시작하지 않는다. 운영·Qwen 경로의 자동 AI 교정은 OFF다.

Precision-2 새 요청은 `transcription=false`, `exclusive=true`, `turnLevelConfidence=true`, `model=precision-2`. 실제 발화자 수를 아는 경우만 `numSpeakers`; 비우면 자동이다. 참석자 수를 대신 강제하지 않는다. API에는 범위 설정도 있지만 이 버전 UI는 정확한 수 또는 자동을 제공한다. Soniox는 자체 diarization을 항상 켜며 예상 수는 기본 문맥의 힌트다. [pyannote API](https://docs.pyannote.ai/api-reference/diarize), [Soniox context](https://soniox.com/docs/stt/concepts/context).

## 처리·보존

- 결합 parent Run과 Soniox/P2 source Run을 구분한다. 자식 ID는 요청 시작 전에 저장한다. Soniox가 완료되면 독립 스크립트를 저장하므로 P2가 실패/대기해도 원문을 열 수 있다. 완료 결과를 새 전사로 덮지 않는다. 앱에서 삭제한 비교본을 매 처리마다 무조건 복원하지 않는다.
- 재개는 같은 Run·같은 입력·원음 해시를 사용한다. 접수 여부가 불명확한 POST는 자동 재제출하지 않는다. 다른 단계의 완료 응답은 그대로 유지한다. 재전사는 새 parent Run이고 기존 수정본·화자 이름은 자동 이식하지 않는다.
- P2 캐시는 session·분석 WAV SHA256·요청 모델·exclusive/turn confidence·numSpeakers 일치를 요구한다. min/max 설정의 과거 결과는 재사용하지 않는다. Soniox 캐시는 같은 session/hash·모델·언어 힌트·화자/언어 감지·실제 context JSON 일치를 요구한다. 캐시 사용은 현재 별칭의 최신 서버 모델 재평가가 아니라 **저장 당시 결과 재구성**이다.
- 각 source의 원응답·request·job ID·요청/보고 모델·생성일·hash, 결합 Run의 양쪽 raw 및 요청 사본, source ID, 결합 알고리즘을 보존한다. 키·서명 URL은 저장하지 않는다. raw/입력/스크립트에는 실제 발언이 있으므로 Git에 넣지 않는다.
- `meetingTerms`는 녹음별 공통 용어다. 새 요청에서 Soniox `terms`, Qwen 로컬 context로 각각 변환한다. 맥락/참석자/직접 참고와 별도 선택한 관련 폴더 발췌를 snapshot한다. 발췌의 이름·hash를 보존하며 전체 폴더를 전송하지 않는다. 날짜·숫자·조건을 문서에 맞춰 고치지 않는다.

## 결합 증거와 읽기

`soniox-p2-v2`: Soniox 토큰의 문자열·공백·순서·원시간·ASR confidence·언어는 불변이다. `asrSpeakerLabel`에 원 Soniox 후보, `modelSpeakerId`와 `sourceIntervalIds`에 P2 후보/근거를 남긴다. 라벨 전체를 사람 이름이나 다른 cluster로 치환하지 않는다.

- 단어 시간이 한 P2 화자에 안정적으로 겹치고 coverage≥0.60이면 배정한다. 기존 Qwen 경로에서 가져온 **초기 설계값**이며 정답 확률이 아니다.
- 복수 화자 경계·실제 동시발화·시간 불명/0길이/coverage 부족은 null. regular와 exclusive 모두 보존한다. exclusive는 소스 분리나 겹말 텍스트 복원 기능이 아니다. [결합 안내](https://docs.pyannote.ai/tutorials/diarization-asr-merge).
- 두 공급자의 인접 안정 토큰에서 화자 전환 여부가 다르면 그 전환 주변에 `provider_disagreement`를 남긴다. 이것은 음성 정답 판정이 아니다. 모든 토큰의 원 후보는 항상 남기지만 한 cluster의 불일치 때문에 전체 회의 모든 단어를 경고하지 않는다. 미확정 구간은 기존 경계/미확정 이슈로 검수한다.
- 화자 구간에 텍스트가 없으면 누락 **의심** marker. A→짧은 B→A는 B 텍스트가 없어도 장벽을 유지한다. 원문에 없는 내용을 채우지 않는다.
- 읽기 `reading-v5` 및 수동 문단 경계는 재사용한다. 문단 수 감소는 품질 지표가 아니다. `review-events-v2`는 원 이슈가 겹치거나 1초 이내이며 전체 30초 이내인 인접 사건을 듣기용으로 묶는다. 이미 겹치는 이슈는 시간 범위를 보존하므로 더 길 수도 있다. 이는 초기 UI 값이고 원 이슈 ID·종류를 삭제하지 않는다.

## 검수·비교 데이터

기존 Script 상세에 같은 오디오 해시 결과 메뉴, 검수 사건 목록/원음 재생, 각 문단의 `검수 기록`, 수정창의 검수 항목을 제공한다. 다른 Run의 Speaker A를 동일 인물이라고 해석하지 않는다.

`reviewRecords`는 전후 revision·원음 hash·원 Turn ID/시각·전후 텍스트·전후 표시 이름·원음 확인 여부·오류 유형·표본 유형·능동 초·메모·기록일을 보존한다. 일반 텍스트/화자 수정도 기록하며 미입력 원음 확인=false, 시간=nil이다. 모델 원문과 기존 immutable LibraryRevisions는 유지한다. 타이머는 명시적으로 시작/정지하고 앱 비활성·저장·닫기 시 정지한다. 취소한 입력은 저장하지 않는다.

오류 유형: ASR, 정렬, E1 귀속, E2 전환/병합, 누락, 짧은 응답, 핵심 의미(용어/숫자/부정/조건), 결합, 표시, 윤문, 미분류, 표본 범위 오류 없음. ‘오류 없음’은 원음 확인을 요구한다. 여러 문제는 별도 검수 기록/메모로 남긴다. 전체 범위를 들은 경우에만 전체 화자 이름 변경의 원음 확인을 표시한다.

평가 JSON은 원문/설정/수정 이력/검수 기록/원음 hash·알고리즘/미확정 lexical 수/누락 marker 수/월 비용 입력을 묶는다. ASR token은 모델별 분절이 다르므로 token 수·미확정 token 비율을 공급자 정확도 순위로 직접 쓰지 않는다. 원음 확인된 오인식 수정도 **정답 후보 검토 가능성**만 갖고 자동 학습하지 않는다. Soniox 전체 출력·모델 합의·LLM 교정·윤문은 정답지가 아니다.

## 같은 기준의 평가와 승격

1. 내부/외부 인물, 2인/3~5인, 짧은/1시간 이상, 조용한/겹말·잔향 회의로 시작한다. 8~12개 회의, 회의별 약5분 검수는 관리 가능한 **시작 제안**이지 통계적 보장이나 수집 완료가 아니다.
2. 문제 표본과 무작위 정상 표본을 분리한다. 동일 원음·동일 구간에서 E1, E2, 짧은 응답 손실, 누락, 미확정, 핵심 의미 오류를 기록한다. 감지 N명·읽기 좋은 문장·경고 없음은 합격이 아니다.
3. 보존 품질을 먼저 통과한 후보끼리 **능동 수정 분/검수한 원음 시간**, 정상 월 현금 비용을 비교한다. 일부 표본 시간으로 전체 회의의 수정 완료 시간을 주장하지 않는다. 업무 총비용에는 청취/수정/되돌리기/유지 시간을 별도로 더한다.
4. 초기 목표로 핵심 오류·짧은 발화 비악화 및 수정 시간20% 감소를 검토할 수 있다. 20%는 미확정 실험 목표이며 달성값이 아니다. 학습/설정 조정/최종 평가 회의는 분리하고 최종 평가는 새 회의에서 한다.
5. Soniox 단독이 동등 품질이면 단순화; P2가 중요한 오류를 지속 감소시키면 결합 유지(현금 목표 별도); Qwen이 여러 회의 유형에서 품질·정렬·안정성·시간·비용을 통과하면 주 ASR 후보; 특정 오류에만 강하면 선택 재전사 후보. 통합 STT가 개선되면 재평가한다. 아무 구성도 통과하지 못하면 ASR·정렬·화자·결합·표시 중 병목을 재측정한다.

Qwen 후속 순서는 기준 성능/누락·청크·한국어 정렬 안정화 → 공통 문맥 실험 → 원음 검수 쌍 축적 → 반복 오류가 남는 경우에만 소규모 미세조정이다. 공식 미세조정 경로의 존재가 개선 보장은 아니다. [Qwen 안내](https://github.com/QwenLM/Qwen3-ASR/blob/main/finetuning/README.md). 현재 MLX 런타임과의 학습 호환성/학습 작업은 미검증. 모델 업데이트와 앱 결합 규칙 변경을 같은 비교에서 동시에 바꾸지 않는다.

## 정상 요금과 실제 청구

2026-09-11 확인: Soniox async는 입력 음성 $1.50/M token, 입력·출력 텍스트 각각 $3.50/M token이다. 공식 참고량 30,000 음성 입력+15,000 텍스트 출력/h로 계산하면 **문맥 제외 약$0.0975/h**이며 한국어 실제 사용량·재처리·추가 문맥에 따라 달라진다. 화자/언어 감지는 포함된다. [공식 가격](https://soniox.com/pricing).

pyannote는 월 포함 크레딧, 초 단위 사용량, 성공 작업 최소20초 과금이며 실제 단가는 계정 plans를 기준으로 한다. 전사를 켜면 STT Orchestration 요금이다. 공개 billing 본문만으로 사용자의 USD19/0.132/0.198 조건을 확정하지 않는다. [공식 billing](https://docs.pyannote.ai/administration/billing).

사용자가 제시한 TIRO Pro13/1000분, Max29/무제한 USD는 비교 참고값으로 남기고 통화·결제주기·실청구를 확인한다. [가격표](https://tiro.ooo/ko/pricing). ‘TIRO보다 저렴함’은 현재 미달성/미측정이며 절약 시간으로 현금 목표를 대체하지 않는다.

설정의 월 비용 화면은 USD만 수동 입력한다. `구독료 + max(0, P2 정상 사용액 − 포함 크레딧) + Soniox 정상 사용액 + 기타 현금 비용`으로 혜택 종료 후 비용을 계산한다. 누락 값은 nil, 확인된 무료 청구만 0이다. 실제 청구액·비교 서비스 청구액·무료 종료일/포함량·근거는 별도다. 예: 가정19/19/13.2/9.75/0이면28.75, P2 사용액을0으로 줄여도28.75. 구독 중단의 효과와 호출 감소의 효과를 혼동하지 않는다. 월 기록은 해당 월 평가 JSON으로 내보내 보관한 뒤 바꾼다. 계정 자동 수집·환율·세금·요금 자동 추정은 하지 않는다.
