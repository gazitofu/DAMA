### Nemotron 3 운영 경로 (2026-10-30 사용자 확정)

정본 스펙은 `notes/nemotron-diarization/nemotron-diarization.src.html`, 상태는 `versions/nemotron-diarization/plan.md`.

- 결합 parent `sonioxNemotron` = Soniox 자식(기존 규칙) + `nemotron` 자식(이 Mac, 음성 전송 없음). 분석 WAV 전체를 FluidAudio 0.18.0 `offline` 프리셋 `processComplete` 1회로 처리한다. 원본 `nemotron-probabilities.f32`(LE Float32, 프레임×8, 10 ms)와 `nemotron-meta.json`을 보존한다. 재사용 키는 session·분석 WAV SHA256·모델 파일 SHA256 목록·FluidAudio 버전·프리셋.
- 구간 `nemotron-intervals-v2`(2026-10-30 r2 사용자 확정): 확률 > 0.5(공급자 기본값, 한국어 실측 전 초기 설계값) 프레임이 같은 채널로 이어진 최대 구간이 일반 구간, 프레임마다 활성 채널 중 최고 확률 채널(동률·무활성은 제외)이 같은 채널로 이어진 최대 구간이 단독 구간(앱 파생, 공급자 exclusive 아님. P2 단독 출력처럼 겹침 프레임도 한 화자로 덮는다). v1(활성 채널이 정확히 하나인 프레임만)은 기존 Run 재현용. 최소 길이·패딩·틈 메우기 없음. confidence는 null. 채널 ID는 Run 안에서만 유효하다.
- 배정은 위 구간에 B2(`soniox-p2-word-v4`) 규칙을 적용하고, 어절 안 lexical이 서로 다른 두 화자 이상으로 갈린 어절만 같은 문장(문장 끝 부호 `. ? ! 。 ？ ！ …`·줄바꿈을 넘지 않음) 안에서 Soniox 화자 후보가 같고 한 화자로 배정된 앞·뒤 이웃 어절의 화자가 하나일 때 그 화자로 맞춘다(2026-10-31 r3 사용자 확정, 블라인드 청취 근거). 판정은 맞춤 직전 배정 한 장으로 하고, 맞추는 어절 안의 미배정 조각과 어절 하나 섬(A [B] A)은 건드리지 않는다. 새 Run 버전은 `soniox-nemotron-word-v3`(v1·v2 Run은 저장 버전으로 재현), engine `hybridSonioxNemotron`. 겹침 단어의 `overlapping_speech` 이슈는 유지하며 P2 경로(v4)와 비교 전용 v5는 바꾸지 않는다.
- 화자 수는 Nemotron에 지정하지 않는다(FluidAudio `numSpeakers`는 채널 절단이라 사용 금지). Soniox 힌트 규칙은 그대로. 녹음 우선 규칙은 Qwen과 같다. 모델은 사용자가 «모델 받기»로 한 번 받고 고정 SHA256 목록과 맞을 때만 쓴다.
- P2 자식이 미완료인 기존 결합 Run과 P2 재사용이 없는 Qwen Run은 재개하지 않는다. 다시 전사는 새 `sonioxNemotron` Run이다.

새 선택의 기본값은 `sonioxNemotron`(2026-10-30). 목록 밖 저장값은 기본값으로 바꾸고 목록 안 선택은 유지한다. 2026-09-11 당시 기본값은 `sonioxPrecision`이었다. 이전 사용자의 엔진 선택은 새 운영 선택 저장 키와 분리해 1회 초기화하며 이후 선택은 유지한다. 구 Run의 미기록 공급자는 pyannote로 해석한다. Qwen 설정·체크포인트·완료 비교 결과는 보존한다. 중단된 Qwen은 새 운영 전사를 막지 않지만 실행 중 작업은 동시에 시작하지 않는다. 운영·Qwen 경로의 자동 AI 교정은 OFF다.

녹음 우선 실행/종료: 녹음 시작은 실행 중인 Qwen 작업에 취소를 요청한 뒤 즉시 진행한다. 녹음 준비·녹음·저장 중 또는 원본 저장이 미확정이면 Qwen 시작/재개를 차단한다. 종료 중에도 새 작업을 시작하지 않는다. 실행 provider는 현재 작업을 시작할 때 고정하며 메뉴 선택이나 이전 Run에서 추정하지 않는다. 앱 종료는 원본 저장과 Qwen 자식 프로세스 종료를 모두 기다리고, 원본 저장에 실패하면 앱을 남긴다. SIGINT에 응답하지 않는 소유 자식은 기존2초 유예 후 종료시키고 실제 종료를 확인한다. 체크포인트·완료 소스는 보존하며 자동 재개/새 API 제출은 하지 않는다. 로컬 취소는 서버 작업·과금 취소가 아니다.

Precision-2 새 요청은 `transcription=false`, `exclusive=true`, `turnLevelConfidence=true`, `model=precision-2`. 실제 발화자 수를 아는 경우만 `numSpeakers`; 비우면 자동이다. 참석자 수를 대신 강제하지 않는다. API에는 범위 설정도 있지만 이 버전 UI는 정확한 수 또는 자동을 제공한다. Soniox는 자체 diarization을 항상 켜며 예상 수는 기본 문맥의 힌트다. [pyannote API](https://docs.pyannote.ai/api-reference/diarize), [Soniox context](https://soniox.com/docs/stt/concepts/context).

## 처리·보존

- 2026-09-13 B2 사용자 확정: 새 결합 Run(새 음성/저장 소스 재사용/재전사)은 `soniox-p2-word-v4`를 사용한다. parent 생성 시 optional `ManagedRun.combinationAlgorithmVersion`에 저장하고 재개 때 그대로 쓴다. 이 필드가 없는 과거 Run은 `soniox-p2-v2`이며 재개 시 v2를 기록한다. 지원하지 않는 버전은 소스 실행 전에 실패하고 최신 정책으로 자동 치환하지 않는다.
- word-v4는 같은 raw 정규화 결과에 승인된 B2 계산을 적용한다. 중간 v2 Run/model은 저장하지 않는다. 비교용 `reconcile`은 기존처럼 별도 Run ID와 수정되지 않은 v2 모델만 받는다. 이미 완료된 v2/A/B/B2와 사람 수정/삭제/AI 이력은 그대로 두며 정책 변경은 새 Run에만 적용한다.
- 결합 parent Run과 Soniox/P2 source Run을 구분한다. 자식 ID는 요청 시작 전에 저장한다. Soniox가 완료되면 독립 스크립트를 저장하므로 P2가 실패/대기해도 원문을 열 수 있다. 완료 결과를 새 전사로 덮지 않는다. 앱에서 삭제한 비교본을 매 처리마다 무조건 복원하지 않는다.
- 재개는 같은 Run·같은 입력·원음 해시를 사용한다. 접수 여부가 불명확한 POST는 자동 재제출하지 않는다. 다른 단계의 완료 응답은 그대로 유지한다. 재전사는 새 parent Run이고 기존 수정본·화자 이름은 자동 이식하지 않는다.
- P2 캐시는 session·분석 WAV SHA256·요청 모델·exclusive/turn confidence·numSpeakers 일치를 요구한다. min/max 설정의 과거 결과는 재사용하지 않는다. Soniox 캐시는 같은 session/hash·모델·언어 힌트·화자/언어 감지·실제 context JSON 일치를 요구한다. 캐시 사용은 현재 별칭의 최신 서버 모델 재평가가 아니라 **저장 당시 결과 재구성**이다.
- 각 source의 원응답·request·job ID·요청/보고 모델·생성일·hash, 결합 Run의 양쪽 raw 및 요청 사본, source ID, 결합 알고리즘을 보존한다. 키·서명 URL은 저장하지 않는다. raw/입력/스크립트에는 실제 발언이 있으므로 Git에 넣지 않는다.
- `meetingTerms`는 녹음별 공통 용어다. 새 요청에서 Soniox `terms`, Qwen 로컬 context로 각각 변환한다. 맥락/참석자/직접 참고와 별도 선택한 관련 폴더 발췌를 snapshot한다. 발췌의 이름·hash를 보존하며 전체 폴더를 전송하지 않는다. 날짜·숫자·조건을 문서에 맞춰 고치지 않는다.

## 결합 증거와 읽기

현행 새 Run의 `soniox-p2-word-v4`는 아래 B2 규칙을 따른다. 기존 `soniox-p2-v2`의 재현·복구 규칙은 다음과 같다. 양쪽 모두 Soniox 토큰의 문자열·공백·순서·원시간·ASR confidence·언어는 불변이다. `asrSpeakerLabel`에 원 Soniox 후보, `modelSpeakerId`와 `sourceIntervalIds`에 P2 후보/근거를 남긴다. 라벨 전체를 사람 이름이나 다른 cluster로 치환하지 않는다.

- 단어 시간이 한 P2 화자에 안정적으로 겹치고 coverage≥0.60이면 배정한다. 기존 Qwen 경로에서 가져온 **초기 설계값**이며 정답 확률이 아니다.
- 복수 화자 경계·실제 동시발화·시간 불명/0길이/coverage 부족은 null. regular와 exclusive 모두 보존한다. exclusive는 소스 분리나 겹말 텍스트 복원 기능이 아니다. [결합 안내](https://docs.pyannote.ai/tutorials/diarization-asr-merge).
- 두 공급자의 인접 안정 토큰에서 화자 전환 여부가 다르면 그 전환 주변에 `provider_disagreement`를 남긴다. 이것은 음성 정답 판정이 아니다. 모든 토큰의 원 후보는 항상 남기지만 한 cluster의 불일치 때문에 전체 회의 모든 단어를 경고하지 않는다. 미확정 구간은 기존 경계/미확정 이슈로 검수한다.
- 화자 구간에 텍스트가 없으면 누락 **의심** marker. A→짧은 B→A는 B 텍스트가 없어도 장벽을 유지한다. 원문에 없는 내용을 채우지 않는다.
- 읽기 `reading-v8` 및 수동 문단 경계를 사용한다. 같은 화자 연속 본문과 동일 미배정 어절을 묶고, 부호는 본문에 붙인다. 누락 의심 marker/전사 없는 감지로 문단을 나누지 않는다. 원 normalized는 보존하며 정책 상세는 `library-script.md`를 따른다. 문단 수 감소는 화자 정확도 지표가 아니다. `review-events-v2`는 원 이슈가 겹치거나 1초 이내이며 전체 30초 이내인 인접 사건을 듣기용으로 묶는다. 이미 겹치는 이슈는 시간 범위를 보존하므로 더 길 수도 있다. 이는 초기 UI 값이고 원 이슈 ID·종류를 삭제하지 않는다.

### 결합 정책과 로컬 비교 (2026-09-13 사용자 승인)

목적은 Soniox 원문 품질과 P2 화자 구분을 함께 보존하는 것이다. 규칙 완화·비교 후 사용자가 B2를 확정했다. A/B는 명시적 로컬 비교용으로 유지하고 B2는 새 Managed Run의 기본 정책으로 연결한다. 저장 응답 재사용은 추가 호출 없이 새 결과를 만든다. 상태는 [soniox-p2-alignment plan](../../versions/soniox-p2-alignment/plan.md) T-06.

- `soniox-p2-timeline-v3`(A): 양수 길이 토큰은 exclusive와의 교집합이 가장 큰 유일한 화자를 선택한다. B800>A200이면 B, A500=B500 또는 교집합 없음이면 null. 기존 coverage0.60과 regular 겹말/경계의 일괄 미배정 조건을 제거하되 경고/구간 근거는 보존한다.
- 0길이의 유효 시각은 `[start,end)`에 들어가는 유일한 exclusive 화자를 후보로 사용한다. 시작은 포함/끝은 제외하며 원시간은 그대로 둔다. invalid_timestamp 경고는 유지하고 면적이 없는 점의 coverage는 nil이다. 시간 자체가 없는 lexical은 미배정이다.
- 닫는 문장부호는 앞 lexical 원문의 화자를 따른다. 문장부호 시간에서 다음 화자가 감지돼도 부호 자체를 새 발화로 취급하지 않는다. 줄바꿈에서는 연결을 끊고, 앞 lexical이 미배정이면 부호도 미배정이다. 직접 및 앞 lexical 근거 sourceIntervalIds를 보존하며 부호의 alignmentScore는 nil이다.
- `soniox-p2-word-v3`(B): A에 어절 조각의 근거 공유를 추가한다. 원문 공백/줄바꿈으로 분리한 lexical 조각들이 시간 순서이고 어절 범위의 exclusive 화자가 하나일 때 미배정 조각에 같은 후보를 준다. 조각 사이 다른 화자 발화, 여러 exclusive 화자, 역행/누락 시간, 다른 화자가 배정된 경계 시점 조각은 공동 배정하지 않는다. 공유 근거는 sourceIntervalIds, 해당 개별 토큰의 alignmentScore는 nil로 기록한다.
- B는 같은 화자의 연속 토큰을 원 Turn으로 구성해 문장부호보다 화자 전환을 중심으로 나눈다. 시작 시간 역행, 다른 화자 구간, 누락 marker, 중단 근거는 장벽이다. A는 토큰별 원 Turn과 기존 문장 읽기 정책을 사용한다. 두 방식 모두 원 토큰을 자르거나 새 문자열/시간을 만들지 않는다.
- `soniox-p2-word-v4`(B2, T-05): B에 짧은 어절 꼬리의 P2 근거 공유를 추가한다. 쉼표/종결/줄바꿈과 ASR label 전환으로 나눈 동일 구절에서 앞 lexical의 P2 화자가 하나이고, 미배정 suffix가 근거 충돌 없는 한 어절일 때만 적용한다. nonnil ASR label은 동일 원문 구절 조건으로만 쓰며 P2 인물과 매핑하지 않는다. 다른 P2 화자의 끼어들기, 시간 역행, 여러 미배정 어절, 동률/후보 충돌은 연결하지 않는다.
- B2 초기 시간 한도는 앞 lexical 끝→꼬리 시작과 꼬리 첫 시작→마지막 끝 각각0~500,000µs(경계 포함)다. 실측 최적값이 아니며500ms/501ms 경계 및 역뮤테이션으로 검사한다. 공유 sourceIntervalIds를 남기고 alignmentScore는 nil이다. 부호는 직접 음성 배정/시간·미배정 경고 대상에서 제외하고 앞 lexical의 소속·근거만 따른다. raw 시간/텍스트/토큰 종류는 보존한다. 기존 A/B 정책과 원본은 변경하지 않는다.
- `soniox-p2-word-v5`(C, T-07, 2026-09-22 사용자 승인): B2에 어절 원자성을 추가한 **비교 전용** 정책이다. 한 어절을 두 사람이 나눠 말할 수 없으므로, B2가 어절 안에서 화자를 갈라 둔 어절에만 어절 전체 구간의 exclusive coverage 최대 화자로 통일한다. 이미 단일 화자이거나 전부 미배정인 어절은 손대지 않으므로 B2에 대해 가산이다. 동률·후보 없음은 그대로 두며 어절 전체를 미배정으로 만들지 않는다. 원문 공백 경계를 넘지 않아 짧은 끼어들기 어절은 보존된다(INV-06).
- v5는 B2의 문장부호 처리·꼬리 공유·`acoustic` 판정을 그대로 켜고, 꼬리 공유 뒤 닫는 부호 부착 앞에서 동작한다. 통일된 토큰의 공유 근거는 sourceIntervalIds에 합치고 alignmentScore는 nil이다. `overlap`/`boundary` 파생 이슈는 토큰별 직접 계산값을 보존한다. 새 임계값·시간·문자열을 만들지 않는다.
- **운영 기본값은 v5로 바꾸지 않는다.** 새 Managed Run은 계속 `soniox-p2-word-v4`를 쓴다. 승격은 사용자가 원음과 대조해 판정한 뒤 별도 태스크로 한다(plan D-02).
- 새 Run ID로 화자 ID를 다시 만들고 Soniox 문자열/공백/순서/원시간/ASR confidence/언어/원 후보를 보존한다. 미배정/경계/겹말/공급자 전환 불일치/누락 의심은 새 배정에 맞춰 재계산한다. 0길이 lexical이 구간 안에 있으면 ‘전사 자체가 없음’ 대신 시간 경고 및 필요 시 미대표 화자 이슈로 남긴다.
- 미배정/문단 감소는 정확도 판정이 아니다. E1/E2·짧은 끼어들기·수정량은 원음 비교 후 판단한다. AI 문맥 후보정은 별도 단계이며 이번 비교에는 실행하지 않는다.

## 검수·비교 데이터

기존 Script 상세에 같은 오디오 해시 결과 메뉴, 검수 사건 목록/원음 재생, 각 문단의 `검수 기록`, 수정창의 검수 항목을 제공한다. 다른 Run의 Speaker A를 동일 인물이라고 해석하지 않는다.

`reviewRecords`는 전후 revision·원음 hash·원 Turn ID/시각·전후 텍스트·전후 표시 이름·원음 확인 여부·오류 유형·표본 유형·능동 초·메모·기록일을 보존한다. 일반 텍스트/화자 수정도 기록하며 미입력 원음 확인=false, 시간=nil이다. 모델 원문과 기존 immutable LibraryRevisions는 유지한다(스크립트를 지우면 그 스크립트의 이력도 지운다). 타이머는 명시적으로 시작/정지하고 앱 비활성·저장·닫기 시 정지한다. 취소한 입력은 저장하지 않는다.

오류 유형: ASR, 정렬, E1 귀속, E2 전환/병합, 누락, 짧은 응답, 핵심 의미(용어/숫자/부정/조건), 결합, 표시, 윤문, 미분류, 표본 범위 오류 없음. ‘오류 없음’은 원음 확인을 요구한다. 여러 문제는 별도 검수 기록/메모로 남긴다. 전체 범위를 들은 경우에만 전체 화자 이름 변경의 원음 확인을 표시한다.

평가 JSON은 원문/설정/수정 이력/검수 기록/원음 hash·알고리즘/미확정 lexical 수/누락 marker 수/월 비용 입력을 묶는다. ASR token은 모델별 분절이 다르므로 token 수·미확정 token 비율을 공급자 정확도 순위로 직접 쓰지 않는다. 원음 확인된 오인식 수정도 **정답 후보 검토 가능성**만 갖고 자동 학습하지 않는다. Soniox 전체 출력·모델 합의·LLM 교정·윤문은 정답지가 아니다.

## 같은 기준의 평가와 승격

1. 내부/외부 인물, 2인/3~5인, 짧은/1시간 이상, 조용한/겹말·잔향 회의로 시작한다. 8~12개 회의, 회의별 약5분 검수는 관리 가능한 **시작 제안**이지 통계적 보장이나 수집 완료가 아니다.
2. 문제 표본과 무작위 정상 표본을 분리한다. 동일 원음·동일 구간에서 E1, E2, 짧은 응답 손실, 누락, 미확정, 핵심 의미 오류를 기록한다. 감지 N명·읽기 좋은 문장·경고 없음은 합격이 아니다.
3. 보존 품질을 먼저 통과한 후보끼리 **능동 수정 분/검수한 원음 시간**, 정상 월 현금 비용을 비교한다. 일부 표본 시간으로 전체 회의의 수정 완료 시간을 주장하지 않는다. 업무 총비용에는 청취/수정/되돌리기/유지 시간을 별도로 더한다.
4. 초기 목표로 핵심 오류·짧은 발화 비악화 및 수정 시간20% 감소를 검토할 수 있다. 20%는 미확정 실험 목표이며 달성값이 아니다. 학습/설정 조정/최종 평가 회의는 분리하고 최종 평가는 새 회의에서 한다.
5. Soniox 단독이 동등 품질이면 단순화; P2가 중요한 오류를 지속 감소시키면 결합 유지(현금 목표 별도); Qwen이 여러 회의 유형에서 품질·정렬·안정성·시간·비용을 통과하면 주 ASR 후보; 특정 오류에만 강하면 선택 재전사 후보. 통합 STT가 개선되면 재평가한다. 아무 구성도 통과하지 못하면 ASR·정렬·화자·결합·표시 중 병목을 재측정한다.

Qwen 후속 순서는 기준 성능/누락·청크·한국어 정렬 안정화 → 공통 문맥 실험 → 원음 검수 쌍 축적 → 반복 오류가 남는 경우에만 소규모 미세조정이다. 공식 미세조정 경로의 존재가 개선 보장은 아니다. [Qwen 안내](https://github.com/QwenLM/Qwen3-ASR/blob/main/finetuning/README.md). 현재 MLX 런타임과의 학습 호환성/학습 작업은 미검증. 모델 업데이트와 앱 결합 규칙 변경을 같은 비교에서 동시에 바꾸지 않는다.

## 정상 요금과 실제 청구

2026-09-11 확인: Soniox async는 입력 음성 $1.50/M token, 입력·출력 텍스트 각각 $3.50/M token이다. 공식 참고량 30,000 음성 입력+15,000 텍스트 출력/h로 계산하면 **문맥 제외 약$0.0975/h**이며 한국어 실제 사용량·재처리·추가 문맥에 따라 달라진다. 화자/언어 감지는 포함된다. [공식 가격](https://soniox.com/pricing).

pyannote는 월 포함 크레딧, 초 단위 사용량, 성공 작업 최소20초 과금이며 실제 단가는 계정 plans를 기준으로 한다. 전사를 켜면 STT Orchestration 요금이다. 공개 billing 본문만으로 사용자의 USD19/0.132/0.198 조건을 확정하지 않는다. [공식 billing](https://docs.pyannote.ai/administration/billing).

설정의 월 비용 화면은 USD만 수동 입력한다. 2026-11-05 usage-bundle1부터 혜택 종료 후 정상 월 비용 = `Soniox 정상 사용액 + AI CLI 구독료 + 기타 현금 비용`이고, 퇴역 pyannote 3항목(구독료·포함 크레딧·정상 사용액)을 셋 다 입력했을 때만 `+ pyannote 구독료 + max(0, pyannote 사용액 − 포함 크레딧)`을 더한다. 주 3항목 중 하나라도 빈칸이거나 퇴역 3항목을 한두 칸만 입력하면 미측정(nil)이다. 누락 값은 nil, 확인된 무료 청구만 0이다. 실제 청구액·비교 서비스 청구액·무료 종료일/포함량·근거는 별도다. 예(검산용 가정값, 실제 요금 아님): 9.75 + 20 + 0 = 29.75 · 퇴역 19/19/13.2를 더하면 48.75 · 19/19/25면 54.75. 구 기록(AI CLI 구독료 없음)은 미측정으로 읽는다. 이전 공식 `구독료 + max(0, P2 정상 사용액 − 포함 크레딧) + Soniox 정상 사용액 + 기타 현금 비용`(예 19/19/13.2/9.75/0 → 28.75)은 과거 기록이다. 구독 중단의 효과와 호출 감소의 효과를 혼동하지 않는다. 월 기록은 해당 월 평가 JSON으로 내보내 보관한 뒤 바꾼다. 계정 자동 수집·환율·세금·요금 자동 추정은 하지 않는다.
