2026-09-10 확정 추가 요청
  • 하단 폴더별 선택 버튼은 ‘폴더 선택… / Finder에서 열기’ 드롭다운 메뉴. Speeches/Scripts 탐색은 유지한다.
  • Script 제목을 수정·저장한다. 제목 변경은 파일 식별자나 목록 정렬 시각을 바꾸지 않는다.
  • 제품의 내보내기는 Markdown(.md) 한 개다. 제목, 녹음 날짜·시간·시간대·길이, 변환 전 입력 화자 수(공백=자동), 맥락, 참고 정보, 각 발화의 화자 표시 이름·시작/끝 타임스탬프·현재 수정 대화를 포함한다. 시간 미제공은 미확인으로 표시하며 원문·미확정/누락 이슈를 숨기지 않는다. 앱이 회의록을 자동 생성하거나 다른 AI에 자동 전송하지 않는다.
  • 변환 당시 입력값의 snapshot은 스크립트와 함께 고정한다. 이후 Speech 메모를 바꿔도 과거 Script의 입력 정보는 바뀌지 않는다.
  • 범위별 표시 이름·문장 수정·제목·녹음 정보를 담는 LibraryScript envelope를 추가하고 기존 normalized transcript v1은 그대로 보존한다. 외부 Scripts에는 .dama.json 편집 파일, 내보내기는 사용자 선택 경로의 .md. 원문 v1을 변경했다고 위장하지 않는다.

  • 첫 선택은 macOS 폴더 선택 창. 재클릭은 해당 목록 전환; 옆 ‘선택’은 위치 변경. 설정에서 두 위치와 API 키를 관리합니다. 시안의 경로는 예시이며 실제 사용자 경로를 고르지 않습니다.
  • 동일 폴더·상하위 중첩 선택은 거부해 파일 중복 수집을 막습니다. 다른 폴더로 바꿔도 기존 파일을 옮기거나 삭제하지 않습니다. 처리/녹음 중 위치 변경은 종료 후 가능합니다.
  • 폴더 권한 상실·외장 디스크 분리 시 ‘폴더에 접근할 수 없습니다. 다시 선택해 주세요.’와 재선택을 제공합니다. 기존 내부 녹음 안전 저장소는 유지하고 선택 Speeches로 내보내기 실패를 안내합니다. 사용자 폴더 문제로 확정된 녹음 원본을 잃지 않습니다.
  • 목록은 녹음 시각 내림차순, 외부 파일은 파일 생성 시각을 사용하고 가져온 시각과 구분합니다. Scripts는 스크립트 생성 시각 순으로, 이름·문장 수정은 순서를 바꾸지 않습니다. 예: 2026-09-10 09:30이 2026-09-09 16:00보다 먼저. 동률은 안정 ID 순입니다.


Speech 선택 → 정보 입력 → 변환 → Scripts
  • 총 참여 화자 수는 선택 입력. 공백이면 자동, 1 이상의 정수만 허용. 설정값은 녹음별 저장하고 변환 시 고정합니다. 현재 API의 numSpeakers로 전달하며 근거 없는 상한을 만들지 않습니다.
  • 맥락과 참고 정보는 녹음별 원문 그대로 저장합니다. 통합 처리 유지 시 로컬 검수 참고용임을 입력란 아래 표시합니다. 모델에 전달하지 않은 정보를 ‘전사에 반영됨’으로 표현하지 않습니다. 맥락으로 원문을 윤문하거나 화자를 추정하지 않습니다.
  • 변환 버튼은 대상 파일·길이·전송 서비스를 제시하는 건별 확인으로 이어집니다. 동의 후 한 번 제출하며 더블클릭·창 재개로 추가 제출하지 않습니다. 비용 인정은 실제 파일 업로드에 대한 포괄 승인으로 해석하지 않습니다.
  • 통합 방식의 처리 중 문구는 ‘화자 분리·전사 중’입니다. 단계별 상태를 공급자가 주지 않으면 퍼센트나 독립 단계 완료를 만들지 않습니다. 결과 준비 후 내부 원 응답·스크립트 저장을 확인해야 ‘변환완료’가 됩니다.
  • 이미 완료한 Speech는 초록색 ‘변환완료’ 버튼으로 대응 Script를 엽니다. 미변환은 빨간색 ‘변환필요’ 버튼으로 상세 변환 영역을 엽니다. 완료 표시는 정확도 확인 완료를 뜻하지 않습니다.
  • 일부 저장만 성공하면 ‘저장 필요’와 로컬 저장 재시도를 제공합니다. 원격 결과가 있는데 다시 API 제출하지 않습니다. 스크립트 외부 삭제 시 완료 이력은 유지하며 ‘스크립트 없음’·로컬 결과 복구를 안내합니다.

Script 열기 → 화자/문장 수정 → 저장
  • 가운데 상단 제목은 ‘스크립트’. 아래 녹음 이름과 생성 날짜, 시간·화자·발화가 시간순으로 표시됩니다. Speaker A, B, C는 해당 Run 내 공급자 화자를 최초 등장순으로 표시하는 이름입니다. Z 이후 AA, AB. 확인할 수 없는 화자는 ‘화자 미확정’이며 새 인물로 추정하지 않습니다.
  • 화자 버튼 클릭 → 변경할 이름과 적용 범위. 기본 범위는 ‘전체 바꾸기’. 대상은 화면 문자열이 아닌 선택한 화자 ID로 결정합니다. 동명인 다른 화자를 합치지 않으며 다른 녹음/Run에는 영향이 없습니다.
  • ‘이 부분만 바꾸기’는 선택 발화 한 개. ‘이 부분부터 바꾸기’는 선택 발화를 포함한 이후의 동일 화자 발화. ‘전체 바꾸기’는 현재 스크립트의 동일 화자 발화 전부. 적용 전 대상 발화 수를 표시하며 취소하면 변경하지 않습니다.
  • 예: A₁ → B₂ → A₃ → C₄ → A₅에서 A₃ 선택. 부분은 {3}, 이후는 {3,5}, 전체는 {1,3,5}. 앞서 부분 변경한 이름도 동일 원 화자 그룹의 전체 변경 대상입니다. 다른 화자 귀속 변경과 이름 표시 변경은 구분합니다.
  • 이름 변경은 사람이 정한 표시 이름이며 공급자 라벨·원 모델 화자·구간 confidence map은 보존합니다. 현재 v1은 Speaker별 displayName만 있으므로 범위별 이름 영속·Markdown 반영에 계약 확장이 필요합니다. 기존 v1 파일은 읽을 수 있어야 합니다.
  • 발화 문장을 클릭해 직접 수정. ‘수정 저장’·‘취소’로 확정하고 자동 맞춤법/문장 다듬기를 끕니다. 모델 원문과 edited text를 분리하고 시간은 자동 재정렬하지 않습니다. 저장 중·실패를 표시하고 미저장 상태에서 다른 문서로 이동하면 저장/이동 취소를 제공합니다.
  • 복수 단어의 문장 편집은 발화 원문을 보존하는 revision 연산으로 추가합니다. 변경된 텍스트에 모델이 주지 않은 단어별 시간을 새로 만들지 않습니다. Markdown과 화면 표시가 같은 저장 revision을 사용해야 합니다.

구현 영향과 확인 범위


재사용

  • 기존 native 시스템 서체·중립 배경·헤어라인·화면 치수. 새 목록 폭 260pt와 상태 색은 이번 후보값.


변경
  • App/DamaApp.swift·StatusBarController.swift·Resources/Info.plist: 공식 표시 DAMA, 메뉴 클릭 동작·2가지 아이콘 색·네 항목·실제 번들 버전.
  • UI/ReviewShell.swift·EditDialog.swift·App/ReviewWorkspace.swift: 두 폴더 탐색·녹음별 변환 정보·발화 편집·이름 범위 선택. 기존 오른쪽 상시 inspector는 접힘으로 전환.
  • ProcessingWorkspace/ManagedProcessor: 화자 수·입력 저장, 지정 폴더에 결과 확정, 성공 Script 연결. 기존 통합 엔진 유지.


신규
  • 2개 폴더 선택·security-scoped bookmark·오류 및 중복 경로 검증, 녹음/Run과 파일 목록 연결, 메타데이터 영속, 안전한 결과 저장.
  • 범위별 화자 이름과 문장 편집의 원문/수정본을 재실행·export까지 보존하는 계약 확장. Speaker.providerId는 현재 유일성을 검사하므로 복제해 임시 화자를 만드는 편법은 쓰지 않음.4


QA는 세 여정으로
  1. 폴더 지정 → 최신 목록 → Speech 정보 저장 → 변환 → Scripts의 최종 스크립트 확인 → 완료 Speech에서 Script 열기. 합성/mock 먼저, 실제 전송 별도 승인.
  2. Script → A₃ 이름의 세 범위·동명이인 → 문장 수정 → 저장·재실행 → Markdown의 동일 결과. 이 변경 영향만 검사.
