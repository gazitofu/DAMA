요구사항

  1. R1 새 변환의 기본 경로를 «Soniox 전사 + Nemotron 3 화자 분리»로 바꾼다. Soniox 단독은 비교 경로로 남긴다.
  2. R2 화자 분리는 이 Mac에서 돈다. 음성을 화자 분리 목적으로 전송하지 않는다.
  3. R3 모르는 화자는 null이고, 짧은 끼어들기를 지우지 않는다(최상위 경계 2·3, INV-06).
  4. R4 pyannote에 새 요청을 보내는 경로는 없앤다. 이미 만든 P2 결과와 스크립트는 지우지 않고 그대로 연다.
  5. R5 녹음이 화자 분리보다 우선한다(최상위 경계 1).
  6. R6 결과에는 원 확률과 모델·라이브러리 버전을 남겨 같은 결과를 다시 만들 수 있게 한다.

잃는 것

P2에 있던 세 가지가 Nemotron에는 없다.notes/diarization-research/research-C2-nemotron-integration.md 0·4절 · NeMo·FluidAudio·speech-swift 소스 확인(2026-10-14).

  • 화자 수 지정. FluidAudio의 numSpeakers 인자는 앞쪽 N개 채널만 읽어 늦게 등장한 화자를 버리므로 쓰지 않는다.
  • 공급자가 만든 단독(exclusive) 구간. 확률에서 앱이 파생한다.
  • 구간별 화자 confidence. 이 유닛은 confidence를 null로 둔다.

Run 구성과 실행 순서

  1. 결합 parent Run(경로 sonioxNemotron)을 만든다. 자식 ID는 요청 시작 전에 저장한다(기존 규칙).
  2. Soniox 자식: 기존과 같다. 같은 음성·문맥 조건의 완료 결과가 있으면 재사용하고 새 요청을 보내지 않는다.재사용 키 = session · 분석 WAV SHA256 · 모델 · 언어 힌트 · 화자/언어 감지 · 실제 context JSON (operating-baseline.md «처리·보존»). Soniox가 끝나면 Soniox 단독 스크립트가 먼저 저장된다.
  3. Nemotron 자식(경로 nemotron, 선택 목록에 없음): 같은 조건의 완료 결과가 있으면 재사용한다. 없으면 이 Mac에서 실행한다.
  4. 둘 다 완료되면 parent가 양쪽 원본을 자기 raw/에 불변 복사하고 결합 스크립트를 만든다.

Nemotron 실행

  • 입력은 그 녹음의 분석 WAV(16 kHz mono) 전체이고 processComplete 한 번으로 처리한다. 저장용 30초 청크를 따로 넣지 않는다(함정 5). 화자 ID는 한 호출 안에서만 유지된다.FluidAudio processComplete는 시작 시 reset() 후 파일 전체를 한 번에 처리 · research-C2 2절.
  • 라이브러리는 FluidAudio 0.18.0 정확 고정, 프리셋 offline이다. 1a 측정과 같은 조합이다.scripts/nemotron-probe/Package.swift exact: "0.18.0" · main.swift Nemotron3Config.offline. speechMask와 segments()는 쓰지 않는다. segments()의 0.2초 최소 길이가 짧은 끼어들기를 지우기 때문이다.
  • 원본으로 두 파일을 남긴다.
    • raw/nemotron-probabilities.f32: little-endian Float32, 프레임 × 8채널 행 우선, 10 ms/프레임.
    • raw/nemotron-meta.json: 분석 WAV SHA256, 샘플 수, 프레임 수, 프레임 길이, 채널 수, 프리셋, FluidAudio 버전, 모델 저장소, 모델 파일 SHA256, 처리 초, 생성 시각.필드는 1a 프로브의 ProbeMeta와 같다 · scripts/nemotron-probe/Sources/NemotronProbe/main.swift.
  • 재사용 키: session · 분석 WAV SHA256 · 모델 파일 SHA256 목록 · FluidAudio 버전 · 프리셋. 원 확률은 결합 규칙과 무관하므로 결합 버전이 바뀌어도 재사용한다.
  • 원 확률 크기는 시간당 약 11.5MB다(360,000 프레임 × 8 × 4 byte). parent 복사까지 두 벌이다.계산값 · 2시간 49분 녹음의 실측 프레임 수로 환산 시 약 32MB.

확률에서 구간 만들기 (nemotron-intervals-v2)

단위는 내부 Int64 µs, 반열린 구간 [start, end)다(INV-02). 프레임 i는 [i × 10,000, (i + 1) × 10,000) µs이고 끝은 녹음 길이에서 자른다. 시작이 녹음 길이 이상인 프레임은 버린다.

  1. 활성: 확률이 0.5보다 클 때만 활성이다. 정확히 0.5는 비활성이다.FluidAudio segments 단일 임계 > 0.5 · NeMo 기본 onset/offset 0.5 · 한국어 실측 전 초기 설계값 · research-C2 1.2–1.3절.
  2. 일반 구간 diarization: 채널별로 활성 프레임이 이어진 최대 구간 하나가 구간 하나다. 최소 길이, 패딩, 같은 채널 틈 메우기는 하지 않는다. 10 ms 한 프레임도 구간이 된다. 서로 다른 채널의 구간은 겹칠 수 있다(INV-07).
  3. 단독 구간 exclusiveDiarization: 프레임마다 활성 채널 중 확률이 가장 높은 채널 하나를 고르고, 같은 채널로 이어진 최대 구간을 구간 하나로 한다. 활성 채널이 없거나 최고 확률이 둘 이상으로 같으면 그 프레임은 단독 구간에 넣지 않는다. 공급자 출력이 아니라 앱 파생값이며, 일반 구간(겹침 포함)을 대체하지 않는다.r2 근거: 설치 앱 Run E33ADFD9(BED2C097) 미배정 1,387 중 1,275(92%)가 두 채널 이상 활성 프레임에만 걸친 토큰 · 저장된 P2 13개 원응답은 겹침 프레임 236,162개를 단독 구간이 100% 한 화자로 덮음 · .build/check-logs/nemotron-diarization/unassigned-diagnosis.txt · 사용자 2026-10-30 «v2로 변경». r1(nemotron-intervals-v1)은 활성 채널이 정확히 하나인 프레임만 썼고, 그 버전으로 만든 Run은 그대로 재현한다.
  4. 화자: 일반 구간이 하나라도 있는 채널만 화자가 된다. 채널 번호 순(첫 발화 순서)으로 «화자 1, 2, …»를 붙인다. 화자 ID는 이 Run 안에서만 유효하며 다른 Run의 화자와 자동으로 잇지 않는다(INV-09).
  5. confidence: 모든 구간에서 null이다. 채널 확률 평균은 앱이 계산한 값이라 공급자 점수 자리에 넣지 않는다(INV-08). 따라서 low_confidence 이슈는 생기지 않는다.

이 규칙의 쪼개짐은 P2와 같은 규모다. 같은 12개 녹음(10.97시간)에서 일반 구간은 시간당 Nemotron 1,864개, P2 1,489개였고, 200 ms 미만 구간은 각각 95개, 236개였다.2026-10-30 이 스펙 작성 중 읽기 전용 측정 · 모집단 = P2 원응답과 1a 확률이 모두 있는 12개 녹음 · Nemotron은 위 1·2 규칙, P2는 원응답 diarization 개수 · 스크립트 notes/nemotron-diarization/fragmentation-check.py (인자 = 내부 Sessions 폴더, .build/diagnostics/nemotron). 텍스트 없는 일반 구간마다 누락 의심 marker가 생기는 기존 규칙은 그대로 둔다.

단어 배정

  • 위에서 만든 일반·단독 구간을 P2 구간 자리에 넣고 B2 규칙(soniox-p2-word-v4)의 배정·문장부호·어절 공유·장벽·이슈 생성을 그대로 적용한다. 새 문턱·시간·문자열을 만들지 않는다.
  • 결합 버전 이름은 soniox-nemotron-word-v2이다. 의미 = «nemotron-intervals-v2 구간 + v4 배정 규칙». 새 Run은 v2, 저장된 버전이 v1인 Run은 재개·재현 때 v1을 쓴다. 지원하지 않는 버전은 실패하며 자동 치환하지 않는다.
  • 겹침 프레임의 단독 화자는 확률 차이가 작아도 고른다(BED2C097 겹침 토큰의 63%가 평균 확률 차 0.05 미만). 실제 동시발화의 귀속 오류(E1) 위험이 있으므로 해당 단어의 overlapping_speech 이슈는 유지한다.
  • Soniox 토큰의 문자열·공백·순서·원시간·ASR confidence·언어와 원 Soniox 화자 후보(asrSpeakerLabel)는 불변이다. 두 공급자의 화자 전환이 엇갈리면 기존처럼 provider_disagreement를 남긴다.

  • 앱 종료는 원본 저장을 기다리고 Nemotron은 취소한다.

모델

  • 저장 위치는 앱 내부 저장소의 Models/nemotron-3-diarization/다. Speeches·Scripts 폴더에 두지 않는다.
  • «모델 받기»를 누를 때만 받는다. 변환 버튼이 모델을 몰래 받지 않는다.
  • 받은 뒤 파일별 SHA256을 앱에 박은 목록과 대조한다. 하나라도 다르면 쓰지 않고 지운 뒤 «다시 받기»를 띄운다. 목록은 /build가 1a 측정 때 받은 파일에서 만든다.
  • FluidAudio가 Hugging Face의 특정 revision을 고정하는지는 미확인이다. 고정하지 못해도 해시 대조가 바뀐 모델을 막는다.

멈춘 P2 Run

  • P2 자식이 완료되지 않은 «Soniox + Precision-2» Run은 재개해도 pyannote에 요청하지 않는다. 현재 1건이 해당한다(B460D5A5).
  • 이 Run의 진행 카드는 «pyannote 화자 분리는 더 이상 사용하지 않습니다»를 보이고 «변환 재개»를 숨긴다. «다시 전사…»는 새 «Soniox + Nemotron 3» Run을 만들며, 조건이 같으면 저장된 Soniox 결과를 재사용한다.
  • P2가 완료된 기존 Run의 결합 재처리는 기존대로 동작한다(네트워크 없음).

화자 수 입력

  • «실제 화자 수 (선택)»은 유지한다. Nemotron에는 전달하지 않는다.
  • 기본 문맥 전송이 켜져 있으면 지금처럼 Soniox에 1~15명 힌트로 전달한다.
  • 스크립트 정보의 «예상 N명 · 감지 M명» 비교는 기존 문구를 그대로 쓴다. 불일치를 자동으로 고치지 않는다.

05

시스템 영향

재사용

  • Soniox 전송·재사용·정규화 전체(SonioxTransport, SonioxNormalizer, reusableSoniox).
  • B2 배정 규칙 본체와 장벽·이슈 생성(SonioxPrecisionReconciler), 계약 검증기, 읽기·검수 화면, 화자 이름 바꾸기.
  • 녹음 우선 판정 allowsLocalInference, 진행 카드 4단계, 스크립트 저장 경로.
  • «예상 N명 · 감지 M명» 표시(speakerCountSummary).

변경

  • TranscriptionProvider: sonioxNemotron(선택 가능, 기본값)과 nemotron(자식 전용) 추가. selectable을 두 항목으로. 저장된 선택값 이전.
  • ManagedProcessor: 결합 실행이 화자 분리 출처(P2 또는 Nemotron)를 받도록 일반화. 멈춘 P2 Run은 재개 시 pyannote를 부르지 않음.
  • P2 구간을 받던 결합 정규화를 구간 출처와 무관하게 공통화. 기존 v2·v4 출력은 바이트 동일 유지.
