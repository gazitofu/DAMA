## T2a 스크립트·수정 이력 보관 (사용자 확정 2026-11-05)

1. 스크립트 파일: 녹음당 "최신 성공본 + 직전 성공본"만 남기고 나머지는 삭제(용량 우선, 사용자 선택 (b)). 사람이 고친 스크립트는 자동 삭제 예외. 실패·부분 완료 결과는 세대로 세지 않음(Astra). INV-09·Soniox 비교본 보존 조항 개정 필요.
2. 화면 표시: 녹음당 "가장 최근에 성공한 결과" 1개. 현행 "결합본 우선"(`ScriptResultPresentation.primaryFile`) 대체.
3. 삭제한 스크립트의 내부 수정 이력: 스크립트 삭제 시 함께 정리. 현재 쌓인 분량은 목록·용량 확인 후 1회 정리. `library-script.md:75` "LibraryRevisions는 남긴다" 개정.
4. 남은 수정 이력: 압축 저장. AI 버전 참조 지문(현재 실제 바이트 SHA256)을 압축 해제 내용 기준으로 바꾸는 계약 변경과 기존 파일 이전·검증 포함.
5. 제목 저장: Enter 또는 입력칸 이탈 시에만 저장(0.5초 자동 저장 폐지).

근거 실측: LibraryRevisions 572개 중 379개(7.6GB, 81%)가 이미 삭제된 스크립트 소속이며 앱에서 읽는 경로 없음(읽기는 AI 버전 참조 7건뿐). 저장 계기: 화자 이름 63%, 문단 15%, 제목 12%, AI 교정 5%. 571회 저장 중 transcript 변경 0회. 최대 파일 gzip 14.8배. Scripts 폴더 전체 309MB.

## T2b 녹음 원본 Drive 이전 (사용자 확정 2026-11-05, 방식 일부 미정)

1. 범위: 48kHz 원본(source 청크, 오래된 녹음 공간의 약 85%)만 이전. 16kHz 분석본(analysis.wav)은 로컬 유지 → 재생·재전사·스크립트 기능 유지.
2. 방식(확정): CRATER 보관 방식(`~/Vault/_setup/projects/backup.py`)을 따른다. DAMA가 설치된 rclone CLI를 실행해 녹음별 무압축 tar 묶기 → `rclone copy` → `rclone check` → 인덱스에 위치·SHA256·복원 정보 기록 → 로컬 삭제. 앱 내 Google OAuth는 만들지 않는다.
   - 계정: 사용자 **개인** Google 계정. rclone remote와 자체 client ID는 사용자가 개인 계정으로 따로 설정(기존 `gdrive:`와 별개). DAMA 설정에서 remote 이름·보관 경로를 지정. 정확한 경로는 `/spec`에서.
   - 순서: 마지막 묶음(묶음 3).
   - 목록 모델: Speeches 번들의 source가 없어도 Speech가 사라지지 않게 "원본: Drive 보관" 상태 추가(현행 scan은 실파일·해시 기준이라 필요).
   - 원격 묶음에 제목·입력 메모 사본을 함께 둔다(인덱스 유실 시 복구용, Astra T3 지적).
3. 자동 삭제: 토글 ON이면 확인 없이 자동 삭제. 48kHz 원본은 Drive 단일 사본이 됨을 사용자가 수용(지속 승인으로 SSOT 기록 필요). 경계 1·함정 8 예외 조항.
4. 기준: 녹음 후 14일 경과. 기본 OFF.
5. 안전장치(초안): 녹음 중·처리 중 제외, 분석본 없으면 먼저 생성, 체크섬 대조 후에만 로컬 두 사본(내부 source + Speeches 번들, APFS 클론) 삭제, 삭제 직전 로컬 해시 재확인, 목록에 "원본: Drive 보관" 상태와 복원 동작.

근거 실측: 내부 녹음 16.1GB/33건. Speeches 사본은 내부본의 APFS 클론(표본 57/57 물리 블록 공유) → 한쪽만 지우면 회수 0. Float32 원본 무손실 압축 7–10%. 14일 경과 26건 10.3GB. 처리·재생은 analysis.wav만 사용(`AudioStorage.prepareAnalysis`).
외부 사실(공식 문서, 2026-11-05 조회, 갱신일 미표기): Drive API files에 sha256Checksum 제공, drive.file은 비민감 범위, 외부·테스트 상태 OAuth 앱의 refresh token은 7일 만료, 데스크톱 loopback redirect 권장. rclone v1.75.2 도움말: 공유 client_id는 2026년 중 중단 예정, 자체 client_id 강력 권장(사용자 `gdrive:` remote는 공유 client_id 사용 중).

## T3 녹음 제목 (사용자 확정 2026-11-05)

1. 저장: 앱 인덱스(`library-index.json`)에 표시 제목. 녹음 파일 이름·manifest는 건드리지 않는다(인덱스 대조 키 = 경로+해시, 변경 시 재가져오기로 입력 메모 연결 끊김).
2. 입력 시점: 녹음이 끝난 직후 제목 입력창(사용자 선택). 조건: 원본 저장 완료 후에 띄우고 저장을 막지 않는다. "나중에"로 넘기면 자동 제목 유지. 이후에도 녹음 상세에서 수정 가능(기본 기능).
3. 스크립트 제목: 녹음 제목을 바꾸면 연결된 스크립트 제목도 항상 같이 바뀐다(사용자 선택). 해석: 제목은 녹음에 하나. 스크립트 제목을 고쳐도 녹음 제목이 같이 바뀐다(양방향). 사용자 이의 시 수정.
4. 녹음 제목 저장은 스크립트 수정 이력을 따로 만들지 않는다. 연결 스크립트 갱신은 T2a 저장 규칙(압축 이력)을 따른다.

## T4 AI 교정·참고 자료 (사용자 확정 2026-11-05, 권장안 전부)

- 4-1 실패 진단·이어하기: 원문 없이 실패 분류만 기록(종료 코드·경과 시간·stderr 바이트 수·인증/설정/네트워크/시간 초과/형식). 성공 청크 누적 저장 + "이어서 교정". 모든 청크 성공 후 적용, 자동 재호출 없음 유지.
- 4-2 자동 반영: 숫자·단위·부정·조건을 바꾸는 변경은 자동 반영하지 않고 "확인 필요".
- 4-3 참고 검색: 앱이 참고 폴더를 로컬 색인(제목·소제목·고유명사). 전사 단어 목록과 문서 용어 목록을 함께 AI에 주어 대응을 찾게 함. 관련도 0 문서 제외. PDF·PPTX·DOCX 포함, XLSX 제외. 파일 수·시간·용량 상한과 누락 범위 표시. 전송 전 발췌 미리보기 유지. AI가 폴더를 직접 읽지 않는다.
- 4-4 맥락 브리프: 전사 후 자동 생성(주제·참석자 후보·용어표, 문서 인용 필수), 교정 시작 화면에서 확인·수정. 확인 안 된 브리프 근거 변경은 자동 반영 금지. 참석자 후보는 확정 명단과 분리. 브리프 확인은 전송 동의를 대신하지 않는다. 기존 입력란 4개는 "고급"으로 접음.
- 4-5 공급자: Codex CLI + Claude CLI. Claude는 `claude --help` 실측으로 같은 격리 수준 확인 후 추가. 설정에서 하나 선택. 동의 문구·engine 문자열을 공급자명으로 일반화.
- 4-6 원칙 4 개정(사용자 동의): AI의 화자 귀속 "의심 표시"를 허용. 조건: 인용 필수, 화자 변경 금지(자동 반영 없음), 음성 근거 이슈와 별도 필드, "우선 확인 후보"로 표시하고 분석 범위·실패 공개, 건수 상한 없음. CLAUDE.md 경계 4·ADR 갱신 필요.
- 4-7 평가: 회의 3건 표본으로 적용 변경을 원음 대조(무교정/기존 교정/새 교정). 승격 판단 기준. 수정 건수는 성공 지표가 아니다.

근거 확인: `CodexCorrectionClient` stdout/stderr 폐기, `CorrectionWorkspace` 실패 시 `edits = []`·고정 문구, 응답 id 완전 일치 검증, `CorrectionSpans` 적용 여부 = 모델 certain·unresolved, `ReferenceFolder` 점수 0 후보 포함·300 항목 상한이 미지원 항목도 계산.
