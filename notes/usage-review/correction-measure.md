# 묶음 3 ① 현행 AI 교정 측정

목적: 현행 교정(`context-correction-6`)이 실데이터에서 돌아가는지, 본문에 반영한 수정이 원음과 맞는지 잰다. 결과로 ②–④ 진행 여부를 정한다. 만드는 것 없음. 이 파일에는 스크립트 제목·본문·이름을 적지 않는다(개수·ID 앞 8자만).

## 판정 단위·표본 (결과 보기 전 고정, 2026-11-07)

- 단위 = 적용된 수정 1개: `correction.edits[].changes[]` 중 `applied == true`. 보류된 수정·미해결 인용은 판정하지 않고 수만 센다.
- B 실측(2026-11-07, 메타데이터): 수정 기록 23 · 그중 표시 문장이 원문과 다른 것 8 · `changes` 8개 전부 `applied` → B 모집단 = 8.
- 표본: 모집단 ≤ 40이면 전부. 넘으면 시드 20261107로 40개를 무작위로 고른다(Python `random.Random(20261107).sample`).
- 판정 라벨(사용자가 원음을 듣고 기입):
  - 맞음 = 교정이 원음과 맞고 원문은 틀렸다
  - 틀림 = 교정이 원음과 다르다, 또는 뜻을 바꿨다
  - 불필요 = 원문도 원음과 맞다(표기·띄어쓰기 차이뿐)
  - 판단 불가 = 원음으로 가릴 수 없다
  - 별도 표시: 의미 변경(숫자·단위·부정·조건) 예/아니오

## 지표·판정 기준 (사용자 확정 2026-11-07, 초기값, 별도 출처 없음)

- 틀림 비율 = 틀림 ÷ (판정한 수 − 판단 불가). 의미 변경 건수.
- 판정은 A(현행 엔진)에 적용한다. B는 구·현행 엔진 비교용이다.
  - 틀림 ≤ 5%이고 의미 변경 0건 → 교정에 가치가 있다고 보고 ②–④ 진행
  - 틀림 > 10% → 교정 기본값 OFF 검토, ④ 보류
  - 그 사이 → 틀린 수정의 원인을 분류한 뒤 결정
- 한계: 표본이 작으면 1건이 비율을 크게 움직인다(8건 중 1건 = 12.5%). 판정 수와 건수를 비율과 함께 적는다.
- A가 실패하면 묶음 1 실패 진단의 분류(종류·종료 코드·경과·stderr 바이트 수)가 ①의 결과다. 원인별 조치를 정한 뒤 다시 실행한다.
