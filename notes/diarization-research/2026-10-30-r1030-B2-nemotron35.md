## 1. 출력 형식과 verbatim 충실도

**형식**
- 기본 출력은 LLM이 생성한 **평문 텍스트**다. 화자 태그 `<spk:0>`~`<spk:7>`은 토크나이저의 전용 특수 토큰이라 디코딩 시 `skip_special_tokens=False`가 필요하다. 카드는 `processor.extract_speaker_dict`로 화자 턴별 dict를 만든다 [카드, 보고서 §2.6].
- 태그 위치: "Start every speaker turn with a speaker tag such as <spk:0>, ..." 형태로 **턴 시작에 한 번** 붙는다 [보고서 부록 A.7]. 카드의 다른 템플릿은 "Put speaker tags <spk:0> <spk:1> <spk:2> <spk:3> on the transcription." [카드].
- **구조화 JSON은 타임스탬프 요청 시에만** 나온다. vLLM 응답의 `ctc_timestamps` 객체: `words`(텍스트, start, end 초, speaker tag), `diarization`(화자 활동 구간), `speaker_tag_to_diarization_speaker`(전사 태그 → 화자분리 화자 매핑), `error`(성공 시 null) [카드]. 카드에 JSON 예시 원문은 없음.

**verbatim / clean 모드 (프롬프트로만 제어)**
- verbatim(기본 프롬프트, `processor_config.json`의 `default_transcription_prompt`와 동일): "Audio transcription. Language: as spoken. Wording: verbatim, including fillers and repetitions. Formatting: punctuation and capitalization. Output: transcript only." [카드, processor_config.json, 보고서 A.1].
- clean: Wording 필드를 "omit fillers and accidental repetitions; keep the remaining spoken wording unchanged"로 바꿈 [카드, 보고서 A.1].
- 더 엄격한 축자 프롬프트(보고서가 Numb3rs·MUCS에 사용): "Transcribe the audio word for word ... Preserve repetitions, hesitations, false starts, incomplete words, and the speaker's grammar. Do not translate, summarize, correct the wording, or complete an unfinished phrase." [보고서 A.2·A.4].
- 다화자 평가 프롬프트(A.7): "Include all spoken words and verbal fillers. Write numbers as spoken. Use no punctuation and no capitalization. Start every speaker turn with ..." 즉 **다화자 평가는 무구두점·숫자 구어형**으로 수행됐다.
- ITN·구두점: 전부 프롬프트 의존. "numbers in their standard written form"(FLEURS) 또는 "Write numbers as spoken"(Numb3rs·다화자) [보고서 A.1·A.2·A.7]. 보고서는 "the wording of the instruction can affect the output in subtle ways, such as the treatment of filler words, numbers, or the choice of script"라고 명시 [부록 A 서두].
- 학습: verbatim(구두점) 27.0%, written-form ITN 9.5%, 비유창성 제거 7.5% 등 과제 혼합 [보고서 그림 6].

**한국어 군더더기("어", "음") 보존 여부: 미확인.** 한국어 verbatim 충실도 측정치 없음. 비유창성 라벨의 출처는 Granary-v2 의사라벨(31.2%) 등이며 한국어 라벨 품질은 미공개 [보고서 §3.1].

**환각·누락·무음·음악**
- HALAS(Earnings-22 환각 주석, 영어): 삽입이 있는 세그먼트 **40.00%**, WER 31.50 [보고서 표 8]. RL이 46.04 → 41.21로 낮춤(평가 코드 상이) [표 5]. 자동 삽입 측정이라 인간 주석 환각률과 다름 [각주 3].
- 생성 루프: "In rare cases ... repeats the same character or phrase until it reaches the token limit." 긴 녹음·코드스위칭·원거리 음성에서 주로 발생. 장문 451개 중 7개, AliMeeting 20세션 중 6개, AISHELL-4 20세션 중 2개에 가드레일 개입. 가드레일 없으면 장문 WER 10.98 → 12.87, AISHELL-4/AliMeeting cpCER 32.91/34.95 → 45.55/55.37. "It cannot recover speech that the model skipped while looping, so a loop still causes deletions." [보고서 §4.1, §4.3, 부록 E]. 가드레일은 출력 텍스트를 바꾸므로 DAMA는 원문과 가드레일 적용본을 분리 보관해야 한다.
- 무음: 무음 → 빈 응답 학습("No-speech abstention", SFT 전반부 + RL 90개 예시). 다만 "part of this data was poorly filtered and contained speech, which caused rare **empty transcripts of actual speech**" [보고서 §3.1, §3.3]. 무음 처리 정량 결과 없음.
- 음악: 음악 이해 학습은 있으나 음악 구간 전사 동작은 미기재 [카드].
- 카드 경고: "The model may misrepresent a recording and generate a plausible transcript", 오류 유형에 "hallucinated speech", "speaker attribution mistakes" 포함 [카드].
- mlx-audio README: 화자 귀속 실행에서 원문에 없는 "Okay."가 추가된 사례 기록 [mlx PR #1087 README].

## 2. 단어 타임스탬프

- **산출**: start와 end 모두 [카드 `words`, mlx timestamps.py]. CTC 어댑터가 ASR 인코더 출력(80 ms)을 전치합성곱으로 **40 ms 프레임**으로 업샘플, 2층 Transformer, 23,862개 다국어 SentencePiece BPE 어휘(+CTC blank), 약 50.25M 파라미터 [보고서 §2.5].
- **방식**: 생성 후 강제정렬(max-sum DP + backtrace). 전사 화자 태그와 화자분리 활동 시각으로 **화자별 DP 행렬**을 구성하고, 화자분리 구간 경계로 각 구간 첫·끝 단어 경계를 보정. 출력은 화자 귀속 단어 타임스탬프와 태그↔화자분리 화자 매핑 [보고서 §2.5]. 생성 텍스트는 바꾸지 않음.
- **각 단어의 화자**: 있음 [카드]. mlx 포트 구현 기준: 단어는 생성 텍스트의 `<spk:N>` 태그를 물려받고, 태그→화자분리 화자 매핑은 CTC 온셋·활동 확률의 IDF 가중 코사인 유사도 + **헝가리안 할당(전역)**, 첫 태그 이전 단어는 speaker `None` [mlx timestamps.py].
- **한국어 분절**: mlx 포트는 공백 분할(`part.split()`)이며 zh·ja만 문자 단위, 한국어는 문자 분할 없음 → **어절 단위** [mlx timestamps.py]. 보고서 표 15도 "Chinese and Japanese use character-level evaluation units; other languages use word-level units". NVIDIA 원본(NeMo/vLLM) 구현의 한국어 분절 규칙은 미확인(mlx가 이식본이라 동일할 가능성은 추론).
- **경로별 가용성**
  - vLLM: `extra_body.mm_processor_kwargs.capture_ctc_timestamps=True`, 서버 `--middleware --trust-request-mm-kwargs`, `VLLM_USE_V2_MODEL_RUNNER=0`, 요청당 녹음 1개, `stream=false`, `n=1` [카드].
  - Transformers: `generate(..., return_word_timestamp_logits=True)` 후 `processor.align_word_timestamps` [카드]. Transformers 정식 릴리스 포함 여부는 미확인.
  - NeMo 단독: 미확인(카드는 NeMo를 학습·파인튜닝 용도로 기재).
  - SGLang-Omni: 단어 타임스탬프·화자 출력 없음. DFlash2 투기적 디코딩: CTC 정렬 비활성 [카드].
  - mlx-audio: **v0.6.3(10-28) 릴리스에는 없음**(PR #1087은 EA 체크포인트, 타임스탬프 미구현). **main 커밋 6a0fd43(2026-10-29, 미릴리스)** "Load official models, add word timestamps, support speculative drafting"이 공식 BF16/FP8/NVFP4 로드와 `word_timestamps=True`(단어별 text·start·end·speaker)를 추가. 커뮤니티 MLX 변환본(nativ-community)은 CTC·MTP 헤드가 빠져 타임스탬프 불가 [mlx README, 커밋].
  - FluidAudio Lite: LLM 없이 CTC 헤드를 **그리디 인식기**로 사용, **단어 시작 시각만**(첫 토큰의 40 ms 프레임), 끝 시각 없음 [FluidAudio 문서·PR #1069]. LLM 텍스트의 강제정렬이 아니다.
- **실패 처리**: vLLM은 `error` 필드 [카드]. mlx 포트는 "No finite CTC alignment path", "No diarization speaker matched transcript speaker {tag}", 태국어 등에서 예외 [mlx timestamps.py].
- **정확도**: 단어 경계 F1@200 ms(보고서 §4.9). 아래 5절 참조. 타임스탬프 정확도 단독 지표는 카드에 없음.

## 3. 화자 귀속 메커니즘

- **주입 방식**: 병렬 전문가 인코더. Nemotron-3-Diarization(스트리밍 Sortformer, 약 100M, **동결**)이 화자 8명분 프레임별 활동 확률을 추정 → 0.5로 이진화 → 정규화 → 고정 사인파 커널(8×1280)로 투영 → 정규화된 ASR 표현에 **덧셈** → 선형 투영(1280→2688)으로 LLM 입력 [보고서 §2.1, 그림 2, 표 1]. 학습 시 참조 화자 구간이 있으면 화자분리 예측을 대체.
- **청크와 화자 일관성 (두 진술이 공존)**
  - 학습 서술: "Since the diarization model also processes 30-second chunks, its speaker indices are local to a chunk, and **the LLM is responsible for keeping the speaker labels consistent across a long recording**." [보고서 §2.1 끝].
  - 추론 서술: 40 s 중심 청크 + 양쪽 4 s 문맥. "the streaming diarization branch trims context internally and **maintains its speaker-cache and FIFO state across chunks**." [보고서 §4.1]. mlx 포트도 녹음당 스트리밍 상태 1개를 청크 간 재사용 [mlx perception.py].
  - 해석(추론): 추론 시 N3D 화자 인덱스는 캐시로 청크 간 이어지지만, 최종 화자 태그는 LLM이 생성하며 장기 일관성의 상당 부분을 LLM이 학습으로 떠맡는 구조다. "텍스트 문맥만으로 화자 추정 금지" 규칙과의 관계는 오디오 조건부이므로 위반은 아니나 LLM 판단이 개입한다는 점은 명시해야 한다.
- **최대 화자**: 8명(N3D 8 슬롯, `<spk:0>`~`<spk:7>` 전용 토큰, 학습 혼합 최대 8명) [보고서 §2.1·§2.6·§3.1].
- **예상 화자 수·참석자 이름·등록 필드**: **없음**. 카드·보고서 어디에도 화자 수 파라미터나 등록 기능 없음. 프롬프트에 태그 4개를 나열하는 예시는 있으나 그것이 인원을 제한하는지는 미확인. N3D 자체도 오라클 인원 입력 없음(기지).
- **어휘·문맥 용어**: 지원. "Context terms: <names and terms>" 또는 "This audio may contain the following words or phrases (some may not be present in the clip): ..." [카드, 보고서 A.5]. 부정·방해 문맥으로 학습해 세션 전체 어휘 제공이 안전하다고 주장(영어 Contextual Earnings-22: 정밀도 98%, 재현율 58% → 96%) [보고서 §4.7]. 카드는 문맥이 오답으로 끌어당길 수 있다고 경고. 참석자 이름을 철자용 어휘로 주는 것은 가능하나 귀속 근거로 쓰면 안 됨(DAMA 규칙).
- **LLM 태그와 N3D 불일치 가능성**: 가능. 태그는 생성 토큰이고 정렬 단계에서 사후 매핑된다. 매핑 실패 시 `error`(vLLM) 또는 예외(mlx) [카드, mlx timestamps.py]. 불일치 빈도 수치는 없음.
- **미지 화자(null) 개념**: 없음. 텍스트는 태그가 붙은 턴으로만 나오며, 첫 태그 이전 단어만 None [mlx]. DAMA 쪽에서 화자 활동 확률 기반 null 처리가 별도로 필요(추론).

## 4. 긴 오디오

- 근거: 카드 "support for recordings up to one hour and a 65,536-token context ... It is not guaranteed to generalize beyond these limits." 보고서 표 1 "Max. recording length (training) 1 hour", 1시간 = 오디오 임베딩 45,000개, 1초 = LLM 입력 12.5개 [§2.1·§2.2]. DeepInfra도 요청당 60분.
- 1시간 초과 공식 가이드: **없음**(카드). 참고로 보고서의 장문 평가는 55분 청크 + 5 s 겹침, VAD 없음 [§4.3]. 이는 평가 프로토콜이지 권장 사용법이 아니며 화자 귀속 평가도 아니다.
- 요청 간 화자 ID: **유지되지 않음**. 카드 "Speaker labels are intended to distinguish speakers within a recording", mlx README "Speaker IDs do not persist across recordings". 2시간 회의를 둘로 나누면 `<spk:0>`이 같은 사람이라는 보장 없음 → DAMA INV-09에 따라 자동 매핑 금지, 별도 Run으로 다뤄야 함.

## 5. 한국어 증거 (전부 NVIDIA 자체 측정)

- **단일화자 ASR**: FLEURS 한국어 CER **2.79%** [보고서 표 23]. 카드 표기는 2.78%(0.01 차이, 평가 코드 갱신 차이로 추정). CoVoST 2 한국어 ASR: 해당 없음("–"). FLEURS LID 100.00%, 음성번역 X→En 24.23 / En→X 27.68 BLEU [표 23].
- **한국어 다화자 cpWER/cpCER: 없음.** 다화자 평가는 영어(AMI, CHAES CH109, Mixer 6, NOTSOFAR-1, LibriSpeechMix)와 만다린(AISHELL-4, AliMeeting)뿐 [§4.8].
- **단어 타임스탬프 F1 83.78 vs 79.44**: 표 15, 데이터셋 **MCS(Multilingual Conversational Speech), NVIDIA 내부 비공개 15개 언어 대화 데이터**. 허용오차 **200 ms**, 시작·끝 경계를 각각 독립 사건으로 채점, 데이터셋 단위 풀링, **화자 무관(speaker-blind)** 채점, 각 시스템이 **자기 인식 텍스트**를 정렬(인식 오류와 시간 오차가 섞인 지표). 한국어 참조 시각은 MFA로 생성(Qwen aligner 사용은 zh·ja만). 한국어 행: Nemotron 3.5 Transcribe **83.78**, Qwen3-ASR-1.7B + Qwen3-ForcedAligner-0.6B **79.44**, Parakeet-TDT-0.6B-v3 –, Whisper-large-v3 + FasterWhisper DTW **49.15** [§4.9, 표 15]. 단위는 어절(공백) 기준 단어.
- **아시아어 회의**: 만다린 원거리 마이크 AISHELL-4 cpCER **32.91**, AliMeeting **34.95**(주 결과, H100 BF16) [표 13]. GB300 단일 평가: BF16 27.64/36.50, FP8 26.96/35.34, NVFP4 34.44/38.10 [표 16]. 보고서 자평: "Mandarin far-field meetings remain a clear weakness". 만다린 다화자 학습 데이터는 두 코퍼스 약 210시간뿐 [§4.8].
- **한국어 학습량**: 고유 22.9천 시간, 학습 오디오 비중 1.77% [표 2]. 다화자 학습 출처로 명시된 것은 Fisher, AMI, ICSI, DiPCo, AISHELL-4, AliMeeting, MLS 기반 시뮬레이션 혼합(최대 8명) [§3.1]. **한국어 실회의 다화자 데이터는 명시되지 않음**(MLS에는 한국어 없음). 카드의 한국어 Multispeaker ASR 체크는 정량 근거 없이 표기된 것으로 보인다(추론). RL 단계에 "additional Thai and Korean examples" 언급(일반 ASR) [§3.3].

## 6. 맥 런타임

**mlx-audio (Python/MLX)**
- v0.6.3 (2026-10-28, PR #1087 머지 커밋 c1e4291): EA(조기 접근) 체크포인트 대상. `task="saa"`로 화자 태그 **지원**, 세그먼트는 화자+텍스트만, **타임스탬프 없음**. LLM만 4-bit 양자화 옵션. 측정(PR 작성자, M3 Ultra, MLX 0.32.4, 53.8 s 2화자 클립, 5회 중앙값): BF16 피크 65.62 GB / 2.729 s(19.7× 실시간), 4-bit 피크 20.37 GB / 1.591 s(33.8×). 정확도 평가 아님 [PR #1087].
- main 6a0fd43 (2026-10-29, **릴리스 전**): 공식 BF16/FP8/NVFP4 로드, 단어 타임스탬프(start·end·speaker), MTP 투기적 디코딩(그리디, 초안 1~8). DFlash2 미구현, 태국어 타임스탬프 미지원 [mlx README].
- 크기·메모리(README의 "measured short-audio runs", 측정자는 README 작성자): BF16 저장 약 67.5 GB / MLX 메모리 약 68.5 GB, **FP8 다운로드 약 34.7 GB지만 로드 시 BF16으로 확장**, **NVFP4 다운로드 약 21.6 GB / 로드 파라미터 약 24.4 GB + 런타임 할당**, 커뮤니티 4-bit 약 19.3 GB(CTC·MTP 없음).
- **M5 Pro 48 GB 함의(추론)**: 타임스탬프가 되는 경로 중 메모리에 들어가는 것은 **공식 NVFP4뿐**. BF16·FP8(확장)은 48 GB 초과. 그런데 NVIDIA는 비영어 정확도에는 FP8을 권장하고 NVFP4는 오차가 더 큼(FLEURS 9.31 → 9.67, 만다린 AISHELL-4 27.64 → 34.44) [보고서 §4.12, 표 16]. MLX에서 NVFP4 정확도가 GPU와 같은지 미확인. 1시간 입력 시 맥 메모리·속도 미측정(미확인). M5 Pro 실측 없음.

**FluidAudio Nemotron 3.5 Transcribe Lite (Swift/CoreML)**
- 구성: 인코더(약 600M) + CTC 헤드, LLM 없음. 48 s 창(40 s 중심 + 양쪽 4 s), CTC 헤드 600프레임 창, N3D(`Nemotron3Diarizer_offline`, FP16, ANE)를 병렬 실행 [FluidAudio 문서].
- 한국어: 문서는 "long-form English transcription"만 기술, 한국어 **미확인**. 어휘는 23,862 SentencePiece(보고서상 다국어 CTC 어휘와 동일 크기)이고 CTC 어댑터는 전체 단·다화자 ASR 데이터로 학습됐다고 보고서가 밝히므로 한국어 토큰은 있을 가능성(추론). 정확도 미검증.
- 출력: 단어 **시작 시각만**(40 ms), 화자 라벨 턴, 선택적 단어 JSON. 끝 시각 없음.
- 화자 부여: 단어 시작 ±약 1 s 안의 가장 가능성 높은 활성 화자, 없으면 **직전 단어의 화자**(DAMA 규칙 3 "가장 가까운 화자로 채우지 않음"과 충돌). 10 ms → 80 ms 평균 후 ±12프레임 최근접 탐색 [PR #1069].
- **"2초 미만 슬롯 제외"는 라이브러리 내부**(`NemotronTranscribeLiteSpeakers`), 총 발화가 아니라 **슬롯별 2 s 미만 발화**를 버림. 설정 가능 여부 미기재 [PR #1069, 문서]. 짧은 끼어들기 화자가 사라져 E1·INV-06 위험.
- 최소 OS: **macOS 15 / iOS 18**(ML Program). PR #1070이 다운로드 전 OS 검사 추가 [PR #1070]. 크기: 필수 산출물 약 1.36 GB(HF 카드: fp16 1.36 GB, int8 683 MB, 4-bit 389 MB). 첫 ANE 컴파일 약 80 s.
- 측정(FluidInference, M5 Pro, AMI EN2002c 49.5분 3화자): 5.53 s(537×), WER 26.4%, cpWER 28.7%. 문서 스스로 "much less accurate than the full model" [PR #1069, 문서].

## 통합 판단 요약 (반론 포함)

- 쓸 수 있는 근거: 한국어 단일화자 CER 2.79%, 한국어 단어 경계 F1 83.78(Qwen 경로 79.44 대비 우위, 단 NVIDIA 내부 데이터·자기 텍스트 기준), 화자 귀속 단어 JSON, 상업 허용 라이선스, $0.12/시간 호스팅.
- 막는 근거: 한국어 다화자 수치 0건, 한국어 실회의 다화자 학습 데이터 미명시, 만다린 회의 cpCER 33–35%, 8명 상한·인원 지정 불가, 1시간 상한과 요청 간 ID 비유지, 화자 태그가 LLM 생성물, 무음 구간 빈 전사·삽입 40% 세그먼트(영어) 등 축자 충실도 위험, 맥에서 타임스탬프 경로는 미릴리스 main 커밋 + NVFP4(비영어 오차 증가)뿐.
- 실패 경로: (1) 짧은 끼어들기가 LLM 턴에 흡수되어 E2 증가, (2) N3D 인원 붕괴가 그대로 남아 E1 해결 안 됨, (3) 2시간 녹음 분할 경계에서 화자 혼동, (4) NVFP4 + MLX 이식의 수치 차이로 NVIDIA 수치 재현 실패.
- 권장 검증 순서(판단): ≤60분 한국어 회의로 DeepInfra(동의 후) 또는 mlx-audio main NVFP4에서 Soniox+P2 대비 화자 수 일치율, E1/E2 건수, 단어 경계 오차, 군더더기 보존율을 같은 녹음으로 비교.
