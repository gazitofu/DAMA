# 화자분리 모델 재조사 · 2026-10-14

사용자 요청: "DAMA에 적합한 모델이 새로 나왔는지, 화자 구분 문제가 심각함." 우선순위(사용자): ① 인원 붕괴 ② E1 오귀속 ③ E2 병합.
방법: 로컬 Run 메타데이터 집계(발언 미열람) + 웹 리서치 4트랙(서브에이전트, 1차 출처 2026-10-14 조회). 메인이 결정 핵심 주장 3건을 1차 출처로 재확인했다. 실호출·음성 전송·코드 변경 없음.

## 1. 로컬 실측이 먼저 말해 주는 것

상세: [local-speaker-count.md](local-speaker-count.md)

- 10-12 결합 Run의 Precision-2 자식이 **HTTP 402로 `waitingForBilling`**. 10-14 녹음은 Soniox 단독 Run만 있고 예상 4명이 2명(50.9/49.1%)으로 나왔다. 최근 체감한 인원 붕괴는 Soniox 자체 화자분리 결과다.
- 예상 3명 이상 12개 세션 중 8개에서 Soniox 자체 화자분리가 인원을 줄였다(3→2 ×4, 4→3, 4→2, 5→3, 7→4). 인원 힌트 유무와 무관.
- P2는 numSpeakers를 보냈으므로 항상 요청 인원과 같다. **인원이 맞는다고 묶음이 맞는 것은 아니다**(분할+병합이 동시에 일어나면 인원은 맞고 E1만 남는다). 원음 대조 미실시.

## 3. 해법이 아닌 것

- **pyannote voiceprint/identify**: 공식 문서 "Voiceprints are used only for identification. They do not improve diarization accuracy."(재확인). 묶음이 정해진 뒤 이름만 붙인다. 3→2 병합은 못 고친다. 1명이 2개 묶음으로 쪼개진 경우 `matching.exclusive=false`로 같은 등록 음성에 두 묶음이 붙는지 보는 용도는 **미검증 가설**.
- Soniox: v5(2026-06-11) 이후 신모델 없음, 화자 수 파라미터 없음(트랙 A).
- OpenAI `gpt-4o-transcribe-diarize`: 2027-02-26 종료 예정. Gemini 3.5 Transcribe: 화자분리 시 30분 한도. DiarizationLM: 문맥 기반 교정이라 최상위 경계 4와 충돌.
- 결합 정책 개선의 상한은 작다(MLC-SLM 2026 2위 시스템: 화자분리 미세조정 −28% vs 병합 정책 교체 −2.4%, 트랙 D). 지금 병목은 결합 규칙보다 화자분리 자체다.

## 4. 반론과 실패 경로

- 인원 강제는 양날이다. 입력 인원이 틀리면(말 안 한 참석자 포함) 유령 화자를 만들어 1명→2명 분할을 강제한다. 현행 UI는 정확값/자동만 있고 min/max 경로가 없다.
- 모든 공개 수치는 영어·중국어 등이다. 한국어 공개 근거는 MLC-SLM 2025 baseline 한국어 DER 23.25(평균 16.44보다 나쁨, 2인 휴대폰 녹음)뿐이다.
- DER은 인원 붕괴와 짧은 발화를 잘 못 잡는다. 녹음별 인원 정확도, E1 건수, A-B-A의 B 누락/병합(E2) 건수를 따로 세야 한다.
- 마이크 거리 차이(근접 vs 원거리)의 DER 효과가 모델 세대 교체 효과와 비슷한 크기다(트랙 D).

## 5. 권고 순서

0. (사용자) pyannote.ai 결제/크레딧 복구 → 10-12, 10-14 녹음 P2 재개. 녹음별 전송 확인 유지.
1. Precision-3 비교 Run: 인원 붕괴가 났던 녹음 4~5개에 동일 numSpeakers로 P3를 새 Run으로 실행(INV-09). 코드 변경은 model 선택값 + P3 출력 보존. 비용은 녹음 시간 × €0.112/h 수준.
2. 정답 표본: 녹음 4~6개의 5분 창에서 사람이 "누가 언제" 표시. 이게 없으면 P2/P3/Nemotron 우열을 판정할 수 없다.
3. Nemotron-3 로컬 인원 검증: 업로드 없이 인원 추정만 해서 사용자 입력 인원과 다르면 녹음 단위 경고. 두 시스템 투표는 근거상 성능을 떨어뜨리므로 불일치는 "확인 필요" 표시로만.
4. 한국어 API(CLOVA, RTZR)는 P3가 정답 표본에서 실패할 때만 1회 비교.

## 6. 후속: Nemotron-3 결합 검토 (같은 날 사용자 요청)

요청: Nemotron-3-Diarization을 Soniox, Qwen, Google Foresight와 결합할 수 있는지. 상세 [C2](research-C2-nemotron-integration.md), [A2](research-A2-foresight.md).

- **Foresight: 결합 불가.** Google 블로그(2026-10-06, 재확인)는 "an experimental app", EmbeddingGemma 2·Gemma 4 기반이라고만 한다. ASR 모델명·언어·화자·내보내기·SDK/API 언급 없음. Gemma 4 오디오 입력은 30초 클립 한도, 타임스탬프·화자 없음(A2 보고).
- **Nemotron 출력(재확인: FluidAudio 소스):** `processComplete([Float] 16kHz) -> (probabilities: [Float], frameCount)`, 10ms 프레임 × 8채널 확률, 채널은 첫 발화 순. `segments(numSpeakers: = 8, threshold: = 0.5, minDurationSeconds: = 0.2)`는 `probabilities[frame * numSpeakers + spk]`로 읽으므로 8이 아닌 값을 넣으면 배열 보폭이 어긋난다(소스 해석). 인원 지정 수단 아님. 0.2초 미만 삭제는 경계 2와 충돌하므로 확률을 직접 쓴다.
- exclusive 출력·화자 임베딩·인원 강제 수단 없음. 긴 회의 저하는 NVIDIA가 정성적으로만 언급, 화자 캐시 264×80ms를 최대 8명이 공유. 오래 침묵한 화자 재등장 동작 미확인.
- NVIDIA 공식 단어 결합 예시: 단어 중점에서 활성 화자 1명이면 배정, 2명 이상 ambiguous, 0명 unassigned. DAMA null 정책과 같은 방향.
- **현행 코드 제약:** `SonioxPrecisionReconciler`·`QwenNormalizer`가 `PyannoteJobDTO`를 직접 디코드하고 `EngineKind`/schema enum에 Nemotron 조합이 없다. 앱 안에서 Script로 보려면 데이터 계약 변경이 필요하다. pyannote 응답으로 위장하는 방식은 출처를 왜곡하므로 금지.

| 조합 | 얻는 것 | 막히는 것 | 판정 |
|---|---|---|---|
| Soniox + Nemotron | 화자분리 현금 0, 화자분리용 음성 업로드 없음, 단어 결합 정책 재사용 가능(구간 변환 시) | 인원 강제 불가(1순위 문제에 손잡이 없음), 한국어·장시간 미검증 | 1단계 오프라인 측정 |
| Soniox + P2/P3 + Nemotron(검증자) | Nemotron 인원 추정을 사용자 입력·P2와 대조해 녹음 단위 경고, 단어별 불일치 표시 | 처리 시간·복잡도 증가, 두 시스템이 같은 약점을 공유하면 경고가 침묵 | 1단계 결과로 결정 |
| Qwen + Nemotron | 완전 로컬 | Qwen 텍스트 품질·0길이 정렬 13%가 병목. 화자분리 교체로 해결되지 않음 | 보류 |

1단계 제안(계약 변경 없음): 별도 CLI로 저장된 분석 WAV에 Nemotron을 돌려 인원·채널 비중·저장된 Soniox 토큰/P2와의 단어 단위 일치를 측정해 `.build/diagnostics/`에만 남긴다. API 호출 0. 필요한 사용자 승인: FluidAudio 패키지 추가와 모델 다운로드(약 190MB, HF).
