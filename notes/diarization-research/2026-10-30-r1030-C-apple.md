# r1030-C: Apple 온디바이스 음성 프레임워크 (macOS 27 사이클) 적합성 조사

- 조사일: 2026-10-30
- 대상 기기 실측: macOS 27.0.1 (BuildVersion 26A434), Apple M5 Pro, Xcode 27.1 (27A9275), SDK 27.0
- 범위: 웹 1차 출처(developer.apple.com 문서 JSON, WWDC26 세션 페이지·자막, Apple Newsroom, macOS 27 릴리스 노트) + 로컬 read-only probe 1회(로케일·에셋 상태 조회만. 에셋 다운로드와 음성 처리는 하지 않음)
- 표기: [1차] Apple 1차 출처, [실측] 이 Mac에서 직접 조회, [3자·미검증] 제3자 보고, 미확인 = 근거 없음

## 0. 결론 요약

1. **macOS 27에서 Speech 프레임워크의 변경은 입력 배관뿐이다.** 2026년 6월 추가분은 `AssetInputSequenceProvider`, `CaptureInputSequenceProvider`, `AnalyzerInputConverter`, `AnalyzerInput`의 새 `init(buffer:)`·`bufferDuration`·`bufferFormat`, `SpeechAnalyzer.Options.ignoresResourceLimits`다. 전사 모델 옵션·결과 타입·속성은 26.0과 같다. [1차]
2. **화자분리·화자식별·화자 변경 감지 API는 없다.** Speech, SoundAnalysis, Foundation Models, Core AI 문서 전체 크롤과 macOS 27 릴리스 노트, WWDC26 138개 세션 목록에 해당 심볼·세션이 없다. WWDC26에는 Speech 전용 세션 자체가 없다. [1차]
3. **한국어 전사는 된다.** `SpeechTranscriber.supportedLocales`에 `ko-KR`이 있고(45개 로케일), `DictationTranscriber`도 `ko-KR`을 지원한다. [실측]
4. **한국어 정확도를 공개 측정한 자료는 찾지 못했다.** 공개 벤치마크는 전부 영어다(LibriSpeech, earnings22, AMI). [3자·미검증]
5. DAMA 판단: **ASR 대체 불가, 화자분리 불가.** 쓸 수 있는 자리는 오프라인 초안과 "누락 발화 증인"(제3 증인) 후보뿐이다. 이것도 한국어 실측 전에는 채택 근거가 없다.

## 2. 플랫폼·권한·라이선스

- **최소 OS**: Speech 모듈 API는 macOS 26.0. 27 입력 헬퍼를 쓰면 macOS 27.0. 화자 관련 기능은 OS 버전과 무관하게 없다.
- **하드웨어**: `SpeechTranscriber`는 하드웨어 요건이 있다고만 되어 있고 구체 목록은 없다. 런타임에 `isAvailable`·`supportedLocales`로 확인하고, 안 되면 `DictationTranscriber`로 폴백하라는 것이 문서 지침이다. [1차]
- **온디바이스 여부**: Apple 권한 문서는 `SpeechAnalyzer` 전사 모듈이 사용자 음성을 Apple 서버로 보내지 않는다고 명시한다. 서버로 나가는 것은 모델 에셋 다운로드뿐이다. [1차]
- **권한**: 같은 문서는 `NSSpeechRecognitionUsageDescription`과 `requestAuthorization(_:)` 절차를 `SFSpeechRecognizer` 전용으로 적는다. 따라서 `SpeechAnalyzer`에는 음성 인식 권한 프롬프트가 필요 없다고 읽힌다. 실측은 미확인. 마이크 권한은 녹음 경로에 원래 필요하다.
- **entitlement**: Speech 전용 entitlement는 문서에 없다. Core AI 릴리스 노트는 백그라운드 Neural Engine 접근에 `com.apple.developer.background-tasks.continued-processing.inference` entitlement가 필요하다고 적는데, 문장은 iOS 27 기준이다. macOS 적용 여부와 Speech 시스템 프로세스에도 적용되는지는 미확인. Speech 모델은 앱 메모리 공간 밖에서 돈다(WWDC25-277).
- **라이선스·비용**: 시스템 API라 호출당 요금은 없다. 상용 앱 사용을 제한하는 Speech 전용 약관 조항은 확인하지 못했다(미확인). Core AI 카탈로그 repo는 BSD-3-Clause이고, 변환하는 개별 모델(Whisper, Parakeet)의 라이선스는 따로 확인해야 한다.
- **재현성 제약**: 시스템이 모델을 자동 갱신한다(WWDC25-277, `AssetInventory` 문서). 문서화된 심볼 중에 모델 버전 식별자는 없다. DAMA의 `algorithmVersion`·벤치마크 계약에 Apple 엔진 버전을 고정해 기록할 수 없다.

## 4. DAMA 적합성 판단

### 4.1 ASR 대체 (Soniox 자리): 불가

- 좋은 점: ko-KR 지원, 무료, 오프라인, 런 단위 시간·신뢰도, 결과 단위 대안, 파일 일괄 API가 있다.
- 막히는 이유:
  1. 한국어 회의 음성 정확도 근거가 0건이다. 영어 회의(AMI)에서도 WER 23%를 넘는다는 제3자 보고가 있다.
  2. `SpeechTranscriber`는 커스텀 어휘가 안 된다(포럼, 미검증). 고유명사 보정 수단이 없다.
  3. 모델이 자동 갱신되고 버전 식별자가 없다. 같은 원음에서 같은 결과를 재사용한다는 DAMA 계약과 정면으로 충돌한다.
  4. 한국어에서 `TimeRangeAttribute` 런의 단위가 미확인이다. Soniox 토큰 타임스탬프와 같은 수준의 정렬 입력이 된다는 보장이 없다.
- 반론: 비용 0과 오프라인은 "API 키도 네트워크도 없어도 녹음" 경계와 맞다. 이 장점은 녹음 안전성에 대한 것이지 전사 품질 근거가 아니다. 대체 사유가 되지 않는다.

### 4.2 화자분리 (Precision-2 자리): 불가

- Apple 1차 출처 어디에도 화자분리, 화자 변경 감지, 화자 임베딩 API가 없다(2026-10-30). `SpeechDetector`는 VAD일 뿐이고, 결과도 현재 오류 처리용이라고 문서에 적혀 있다.
- 사용자의 최악 문제인 화자 수 붕괴, 오귀속(E1), 턴 병합(E2)은 Apple 프레임워크로 손댈 수 없다.
- Core AI는 서드파티 diarization 모델을 돌릴 런타임일 뿐이다. Apple이 제공하는 diarization 모델은 없다. 세션 324는 "작은 diarization 모델로 회의 화자 식별"을 활용 예시로 언급하는 데 그친다. 이 경로는 결국 Apple 기능이 아니라 별도 모델(pyannote·Sortformer 계열) 선택 문제이고, 다른 리서치 트랙의 범위다.
- 참고: 제3자 Sortformer 패키지는 최대 4화자로 적혀 있다. DAMA 목표(2–7명)에 미달한다. [3자·미검증]

### 4.3 제3 증인: 조건부 후보, 현재 근거 부족

- 쓸 수 있는 역할은 하나다. **누락 발화 증인**: 같은 시간창에서 Apple 전사에는 텍스트가 있고 Soniox 토큰이 비어 있으면 "짧은 발화 누락 가능" 플래그를 띄운다. INV-06(A→B→A에서 B 누락 시 A 병합 금지)의 검수 신호로 쓰는 것이다. 화자 귀속에는 쓰지 않는다.
- 결과 경계(`Result.range`)로 쉼 기반 분절 신호를 얻는 것도 가능은 하다. 다만 이것은 화자 경계가 아니라서 E2 판정 근거로 승격하면 안 된다.
- 실패 경로:
  1. Apple 엔진 자체의 누락·환각 때문에 거짓 플래그가 늘어 검수 시간이 오히려 늘어날 수 있다.
  2. 모델 자동 갱신으로 같은 녹음의 증인 결과가 시점마다 달라진다. 증인 출력을 Run 산출물로 저장하고 재계산하지 않아야 한다.
  3. 2시간 파일 동작, 메모리, 분석 시간이 미확인이다. 동시 분석 상한(`insufficientResources`)에 걸릴 수 있다.
  4. 에셋 예약이 5개로 제한되고, 저장 공간에 따라 기기마다 다르다.
- 채택 전제: 한국어 실측으로 (a) CER, (b) 짧은 발화 재현율, (c) 런 타임스탬프 단위와 오차를 확인해야 한다. 이 검증에는 ko-KR 에셋 다운로드(Apple 서버, 사용자 음성 전송 없음)가 필요하다. 다운로드이므로 사용자 승인 대상이다. 이번 조사에서는 실행하지 않았다.

### 4.4 Foundation Models 오디오 입력: 해당 없음

- 시스템 모델은 텍스트와 이미지만 받는다(27.0). 오디오 입력 심볼은 없다. 27.2 베타의 데이터 첨부는 서드파티 `LanguageModel` 구현자가 받는 구조라서 Apple 모델이 오디오를 이해한다는 뜻이 아니다. 온디바이스 컨텍스트가 4K라서 2시간 전사본 후처리에도 맞지 않는다.

## 5. 미확인 목록

- 한국어 `SpeechTranscriber` CER, 한국어 회의 음성 품질
- 한국어에서 `TimeRangeAttribute` 런 단위(어절·토큰·구)와 시간 오차
- 2시간 단일 파일의 동작·메모리·처리 시간, 문서화되지 않은 길이 상한 존재 여부
- `installedLocales`와 `AssetInventory.status` 불일치 원인
- `SpeechAnalyzer`에서 음성 인식 권한 프롬프트가 실제로 생략되는지
- 백그라운드 inference entitlement의 macOS·Speech 적용 여부
- Speech API 상용 사용에 대한 별도 약관 조항 유무
- ko-KR 외 인도 언어 로케일 추가 시점
- 통화 녹음 전사의 "Speaker 1/2" 라벨 여부(제3자 진술이 서로 다름. API 노출이 없으므로 DAMA와 무관)
