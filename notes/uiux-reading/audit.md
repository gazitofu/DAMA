# UI/UX 진단: 읽기에서 원음 확인과 수정까지

2026-09-12 · DAMA 0.4.7(17) · HEAD `63bd0ca` · `work/m0-fixture-review`.

이번 진단의 축: 첫 화면의 정보 위계, 문단 읽기, 구간 재생, 편집/취소/저장 안내, 검수 사건 탐색, 같은 원음 결과 선택, 키보드·작은 창 대응. 종료 조건: 각 축의 실제 화면 또는 활성 코드 근거와 수정 우선순위·미측정을 기록한 후 닫는다. 추가 전수 검수로 확대하지 않는다.

## 결론

본문보다 전사 설정과 검수·모델 안내가 먼저 나오고, 읽기 문단을 편집할 때는 공급자의 짧은 원구간으로 되돌아간다. 재생과 검수 사건 목록도 본문의 현재 위치와 충분히 연결되지 않는다. **정보 배치 → 구간을 한눈에 보는 편집 → 재생·검수 위치 연결** 순서로 수정한다. 미확정·짧은 B·누락 장벽을 없애는 방식으로 화면을 정돈하지 않는다.

## 실측 방법과 한계

- CUA로 설치된 앱의 스크립트 기본 화면, 문단 편집창, 구간 재생 중 화면, 같은 원음 결과 메뉴/전환, 화자 이름 변경창을 열었다. 대사/이름 수정창은 입력·저장 없이 취소했다. 실제 저장 파일은 읽기 전용으로 다뤘다.
- 결합 결과의 검수 기록1건/원음 확인0건/검수 사건259개, 저장 목록8개를 관찰했다. 이는 UX 재현 대상의 개수이며 정확도 지표가 아니다. 재생 명령 후 정지 아이콘을 확인했으며 음성 내용 정답·출력 지연은 판정하지 않았다.
- 기본 창 screenshot은 1252×768 이미지, 편집 sheet screenshot은 520×806 이미지였다. 이 값은 도구 이미지 크기이며 macOS point 규격으로 환산하지 않는다. 앱 코드의 기본1180×760pt/최소900×600pt, 본문17pt+행간7pt와 구별한다.
- 표본은 실제 저장된 한 녹음의 결합본/단독 결과이며 모든 회의·모든 환경으로 일반화하지 않는다. 900×600 실제 창·라이트 모드·VoiceOver 청취·키보드 전체 여정·장시간 프레임 성능·새 저장/내보내기 여정은 이번에 재시험하지 않았다. 기존 검증을 새 UX 검증으로 표시하지 않는다.
- TIRO는 [공식 공개 페이지](https://tiro.ooo/ko/)의 데모를 브라우저에서 확인했다. 제목 아래 메타정보 한 줄, 본문 탭, 별도 보조 영역 배치를 참고한다. 로그인 제품의 편집/재생 동작이나 정확도 주장은 검증하지 않았다. 원음·회의 맥락을 TIRO에 전송하지 않았다.

## 첫 수정 묶음

1. **본문 중심 배치**: 새 전사 설정을 Speeches로 한정, 제목/메타정보 압축, 검수/정보 inspector, 중립 본문 바탕과 절제된 화자 표식, 명시적인 행 선택/수정 동작.
2. **편집 연결**: 원구간21개를 큰 입력칸21개로 펼치지 않는다. 문단 내 원구간 선택과 단일 편집칸, 미리보기, 저장 실패 시 draft 유지, 취소 시 저장0건. 검수 기록의 기존 필드/선택은 유지하되 보조 입력은 접는다.
3. **재생·검수 연결**: 현재 재생 위치와 범위를 하단에서 확인. 검수 사건을 선택하면 관련 문단으로 이동. 녹음 중 차단과 시간 미확인 안내 유지. 음성 시간이나 화자를 추정하지 않는다.

문단을 완전히 자유로운 한 입력칸으로 바꾸려면, 여러 Turn에 걸친 수정 문자열을 어느 ID에 저장할지와 수동 분절/Markdown/AI 이력의 관계를 별도 결정해야 한다. 이번 첫 묶음은 **원구간 선택 편집**으로 입력칸 탐색 비용을 줄인다. 이를 자유 문단 편집 완료라고 부르지 않는다.

| 여정 | 완료 기준 |
|---|---|
| Script 열기 → 읽기 → 정보 펼치기 | 스크롤 없이 첫 본문 구간이 보이며 기본 모델/전송 폼이 본문을 밀어내지 않음. 같은 원문/문단 수와 모든 경고에 접근 가능 |

| 900×600 / 1180×760 → 키보드·접근성 | 저장/취소·재생 제어가 가려지지 않고 포커스 순서가 시각 순서와 맞음. 닫은 inspector는 탐색 대상에서 제외. 라이트/다크 실물 확인 |

## 근거와 상태

홈/appdev/repo 지침, 공통10종·공유 트리·수치·외부 미디어·워치독·리뷰 종료 규율은 같은 세션에서 읽은 본문을 재사용했다. 착수 규율 파일 목록/설명과 홈/appdev/repo를 재확인하고 목적/게이트/리뷰 종료를 재독했다. `/spec`·`/plan`, 양식 README/template, 설계00·01, 기존 채택02·03·04·06·API verified, library-script/operating-baseline 계약, tone2종, 활성 UI·App·SegmentPlayback 코드를 근거로 한다.

앱 코드·저장 데이터·tone 정본은 이 진단에서 변경하지 않는다. 다음 산출물은 `uiux-reading.src.html`/빌드 HTML의 수정 시안이다. 화면 확인 후 전용 plan으로 구현한다. 착수 타 소유 dirty7(build 커맨드·README·Qwen evaluation·dev·m0/m1/m2 plan)은 보존한다.

## 시안 검증 (r1)

- [수정 시안](uiux-reading.html), 원문 `uiux-reading.src.html`. 프로젝트 template 복제 후 진단/정책/조작 시안/규격/문구/영향 범위를 작성, `_build.py` 성공(각주4건, 자립 HTML). HTML의 `data-state="open"`은 화면 확인 대기이며 plan/앱 구현 완료가 아니다.
- CUA 브라우저에서 판정 블록/각주 팝오버, 라이트/다크, 원구간 선택·draft 유지·취소·저장 반영·실패 시 입력 보존, 검수 사건의 문단 선택 이동, 녹음 중 재생 차단, 빈 상태 내보내기 차단을 확인했다. 브라우저 console error 없음. 900×600 브라우저에서 편집 dialog 높이474px, 입력칸1개와 dialog 안의 저장/취소 footer를 시각 대조했다. 이는 HTML 시안 검사이고 네이티브 검증을 대신하지 않는다.
- 한 번의 네이티브 이름 변경 클릭 직후 AX 조회가 실패했으나, 다음 상태 조회에서 sheet와 전체 기본/785개 대상 표시를 확인했고 취소했다. 클릭을 반복하거나 저장하지 않았다.
- 원래 결합본/목록8개/검수 기록1건·사건259개로 복원. `.build/diagnostics/uiux-reading/preservation.json`: 이전 고정 manifest의14파일/8Script SHA256 불변. 새 전사·AI 실행·음성 전송·실제 수정 저장 없음. 앱 버전0.4.7(17) 유지.
- 검사 범위를 닫는다. 이후는 시안의 배치와 원구간 선택 편집 방식 확인 후 전용 plan. 자유 문단 편집을 선택하면 저장 연결/분절/이력 계약부터 별도 설계한다. 기존 dirty7은 수정·stage하지 않는다.
