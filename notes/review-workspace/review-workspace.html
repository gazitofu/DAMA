01
원문을 지키는 검수
좋은 문장보다 누가 말했는지 확인할 수 있는 원문을 우선한다. 알려지지 않은 화자는 미확정으로 남기고, 짧은 다른 화자의 구간은 독립된 행으로 보존한다.1
  1. 녹음은 먼저. 제목·화자 수·API 키 입력은 녹음 시작을 막지 않는다.
  2. 확인할 곳으로 이동. 다음 확인 구간은 미확인 이슈로 이동하며, 이슈 확인과 화자 수정은 별개다.
  3. 근거를 옆에서 읽기. 현재 귀속·모델 후보·공급자 점수·시간 겹침·사람 확인을 구분한다.
  4. 수정도 원본과 함께. 모델 결과와 사용자 수정본을 분리하고 내보낼 판을 명시한다.
비범위: 요약·회의 챗봇·실시간 자막·시스템 오디오·입력 장치 선택·로컬 WhisperKit·모델 비교 UI·배포·실음성/API 검증. 제품 코드와 계약 파일은 이 단계에서 수정하지 않는다.

외부 전송 정책
기본은 ‘매번 확인’. ‘종료 후 자동 전송’은 사용자가 외부 전송·과금을 확인한 뒤에만 켠다. 녹음마다 ‘로컬 저장만’이 전역 자동 전송보다 우선한다. 업로드가 시작된 후 ‘로컬 저장만’으로 소급 변경해 서버 삭제를 약속하지 않는다.3
  • 키가 없으면 전사만 ‘API 키 필요’로 대기한다. 녹음 시작은 활성 상태다.
  • 매번 확인의 동의 창을 닫으면 전송하지 않고 ‘전송 확인 대기’로 남긴다.
  • 자동 전송과 키 누락이 함께 있으면 키 저장 후 대기열을 재개한다. 이미 받은 녹음별 동의와 원본 가용성을 다시 검사한다.
  • 파일 가져오기: M4A/WAV를 선택하고 원본 복사·검증 뒤 전송 정책을 적용한다. 실패 시 빈 세션을 정상 기록으로 표시하지 않는다.
  • 화자 수는 실제로 말한 사람 수. 자동 / 정확히 / 범위를 배타 선택하고 양의 정수·최소≤최대를 검증한다. 오류가 있어도 녹음은 유지하며 전사 제출만 막는다.

검수·수정·내보내기
  1. 선택: 클릭으로 한 Word, Shift+클릭으로 같은 Run의 연속 ordinal 범위를 선택한다. 한국어 어절을 임의로 다시 토큰화하지 않는다. 발화 행 선택과 ‘구간 듣기’를 분리하여 단어 선택 중 갑작스러운 재생을 막는다. 이는 설계 01의 클릭 즉시 재생에 대한 채택한 화면 변경다.
  2. 화자 변경: 선택 Word만 기존 Run의 화자 또는 ‘화자 미확정’으로 바꾼다. 모델 후보는 보존한다. 선택 없음·marker에서는 단어 귀속 명령을 비활성화한다.
  3. 이름 변경: 선택 화자의 표시명만 현재 Run 안에서 바꾼다. 화자 병합이나 다른 Run의 실명 매핑이 아니다. 빈 이름은 저장하지 않는다.
  4. 직접 텍스트 수정: P0는 한 Word를 선택해 명시적으로 대체한다. 여러 Word 선택 시 ‘한 단어를 선택해 주세요’. 모델 text는 유지하고 editedText를 기록한다. ‘시간 재정렬 안 됨’을 표시한다.
  5. Turn 분리: speech Turn 내부 Word 경계에서만 분리한다. 원래 단어 순서·텍스트·시간은 유지하고 새 Revision에 두 Turn을 보존한다. 단일 Word 내부를 자르지 않는다. 이후 귀속 재구성에서도 사용자가 지정한 분리 경계를 보존해야 한다.
  6. 누락 수동 입력: 기존 marker를 인식 텍스트로 전환하지 않는다. 시간 선택과 수동 입력 provenance가 완성되기 전에는 ‘누락 발화 직접 입력 · 미지원’으로 비활성 표시한다.
  7. 확인함: 현재 이슈만 acknowledged로 변경한다. 화자·텍스트·marker는 그대로다. ‘미확인으로 되돌리기’와 Undo를 제공한다. resolved는 원인이 해소됐음을 별도로 판정할 때만 사용한다.
  8. 저장: 새 Revision을 영속 저장한 뒤에만 ‘저장됨’. 저장 중 내보내기는 비활성, 실패 시 ‘저장하지 못했습니다’와 재시도·변경 취소를 제공한다. 저장 실패 상태로 창을 닫으면 경고한다.
  9. 내보내기: JSON/TXT 및 ‘현재 수정본 / 자동 결과 원본’을 명시 선택한다. 기본은 현재 표시 중인 판. 미확정·겹침·누락 marker는 유지하고 다른 AI에 자동 전송하지 않는다.

  • 설계 01의 클릭 즉시 재생을 ‘행 선택 + 구간 듣기’로 분리한다.

  • 최소 폭 Inspector는 접기·근거 보기 오버레이 정책으로 구체화한다.
새로 구현할 것
  • 실제 메뉴바·패널·온보딩·동의·검수 창 및 상태 연결. 현재 .xcodeproj와 DamaCore는 없다.

  • 원음 플레이어·검색·다음 이슈 이동·내보내기·오류 복구 UI.
이 HTML은 /plan과 /build의 입력 문서다. 앱 코드·계약·fixture를 생성하거나 바꾸지 않는다. result_expired는 처리 상태 UI에 매핑하며 normalized IssueKind에 추가하지 않는다. 최소 OS·서명 identity·실계정 테스트는 해당 유닛 /plan의 전제이고 이 화면 컨펌으로 해결되지 않는다.
